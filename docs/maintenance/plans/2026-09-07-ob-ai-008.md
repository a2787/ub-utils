# OB-AI-008 — 抖音一键加载与 AI 分析闭环

- status: verified
- date: 2026-09-07
- scope: 抖音详情页的一键式评论/弹幕加载、稳定等待、AI 分批分析与现有人工审核闭环。
- non-goals: 不调用抖音私有接口；不执行平台举报、拉黑、关注、发帖等写入；不自动确认 AI 候选或写入本地名单；不把平台显示总数猜成已加载数；不做无界面、无上限的滚动；不改变 B站或其他平台入口；不绕过验证码、登录或安全验证。
- dependencies: OB-AI-002; OB-AI-007 的批处理/超时证据见历史计划

## 问题定义

当前抖音的“评论屏蔽”管理器负责额外加载评论/弹幕，设置页的“AI 分析”只负责分析当时已经观察到的记录。用户必须手工串联两个入口，并且在加载完成后再次进入设置页，容易把新记录漏在分析之外。目标是把“加载—收集—分析—审核”变成一次插件操作，同时保持现有身份安全和人工确认边界。

## 设计边界

1. 复用已经经过真实页面验证的评论管理器和弹幕时间轴加载路径，不新增私有 API、接口逆向或平台写入。
2. 把一次操作建模为可取消的 run：拥有唯一 run/session 标识，记录活动视频键、加载阶段、观察记录数、已分析数和错误；换片、关闭面板或用户取消时收尾旧 run。
3. 加载完成后以当前会话中实际观察到的规范化文本建批；批次大小仍由现有 AI 分析协议控制，重复记录按稳定记录键去重，不按页面显示总数做承诺。
4. 分析结束进入现有人工审核态。自动化只负责准备候选，不能替用户确认候选、写本地名单或点击抖音平台的举报/拉黑等控件。
5. 进度文案必须区分“正在加载”“正在分析”“已完成”“已取消”“失败”，不能用持续 loading 掩盖超时或桥接失败。

## 实施拆分

- [x] 审计现有 `commentManager`、抖音弹幕时间轴扫描和 `AI.run` 的取消/会话边界，确认可复用入口与必须抽出的 Promise。
- [x] 增加一键编排 API，支持阶段进度、AbortSignal/取消、活动视频校验、重复运行互斥和清理。
- [x] 在抖音 AI 入口提供“加载并分析本页”动作；保留已有“仅分析已观察内容”能力供高级/故障恢复使用。
- [x] 为评论、弹幕、播放器状态变化、取消、重复记录和分析失败补人工合成回归；旧的手工两步路径仍须通过。
- [x] 在用户授权的专用 Chrome 登录态抖音详情页完成只读真实验证，记录实际加载量、批次和审核状态；未点击平台写入控件。
- [x] 更新 README、当前 changelog、CURRENT、PLAN/HISTORY 状态和交接命令；未创建新 tag、Release 或执行平台写入。

## 验收标准

- 用户点击一次插件入口后，评论和弹幕的受控加载、稳定等待、AI 分析和审核态连续完成，不再需要手动切换到设置页。
- 最终分析数量来自实际观察记录；加载后新增记录会被纳入，同一记录不会因 DOM 重用或多次扫描重复请求。
- 取消、超时、换片和重复点击都能释放定时器、监听器、请求与旧会话引用；旧 run 不得覆盖新 run 状态。
- 无可靠身份的记录仍只能只读分析/展示；人工审核和本地名单写入门槛不降低。
- 本地回归、语法、文档和 diff 门禁通过；专用 Chrome 真实证据明确标注 `real-site verified` 或 `blocked`。

## 回滚点

保留现有“评论管理器加载”和“设置页仅分析已观察内容”两个入口；若一键编排在真实页面出现结构或生命周期问题，可仅关闭新入口并回退到这两个已验证路径，不删除旧代码、不触碰网关凭据。

## 证据

- `structure regression`：`node test/ai-autoload.cjs` 3/3；覆盖一次调用加载评论/弹幕、播放器状态 class 变化不误取消和 AbortSignal 取消；语法、受影响 AI/评论/弹幕回归及文档门禁通过。
- `real-site verified`：2026-09-07 用户授权专用 Chrome 登录态 `douyin.com/video/...` 一键运行，评论/弹幕实际观察记录最终为 365 条，弹幕时间轴 55/55，5 批完成 365/365，审核框 28 条候选，错误为 0；未确认候选，未点击平台写入控件。
- `blocked`：匿名抖音入口仍可能进入验证码中间页；本计划不以匿名入口替代登录态证据，也不把平台显示总数当作已加载总数。
