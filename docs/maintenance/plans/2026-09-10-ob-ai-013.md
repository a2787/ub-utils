# OB-AI-013：独立 AI 评测集与事实检索部署方案

状态：`in_progress`。用户已授权按本方案逐阶段实施；当前已完成离线评测、受控本机 broker、shadow/canary 接入和回归验证，待发布链及真实来源/线上模型观察收口。真实来源未配置时继续保持 `blocked`，不把 mock 结果写成线上精度。

## 目标与边界

目标是把“AI 屏蔽是否识别准确”和“事实是否有外部依据”拆成两个可测、可回滚的系统：先用独立本地评测集量化当前模型/提示词的误报与漏报，再在不改变人工确认和身份门禁的前提下评估受控事实检索。

必须保持的边界：

- AI 仍然只产生候选；任何屏蔽都必须由用户明确确认，检索结果不能直接写入名单，也不能替代人工审核。
- “没有引用、尚未核查、语境不足”不等于“内容为假”；事实证据不足的默认动作是 `defer`，不是 `block`。
- 评测集只允许人工合成、脱敏或获得明确许可的样本；不保存 Cookie、Token、真实用户标识、原始页面 URL 或未脱敏正文。
- 身份解析、hash-only、用户卡片校验和本地名单撤销继续遵守 OB-AI-012；评测/检索不得放宽身份门禁。
- 第一阶段不接公共搜索、不改变现有 loopback 网关、不启用自动屏蔽、不修改平台写入边界。

## 阶段 0：冻结基线与问题定义

在任何模型、提示词或检索实现前，冻结 v0.53.1 的以下快照：源码 SHA-256、提示词版本、响应 schema、网关模型/配置标识、客户端规则版本、AI 批次上限、时间戳和测试运行器版本。当前版本作为 `baseline-v0.53.1`，只允许通过显式版本号产生后续候选。

先把决策拆成四层，避免用一个“准确率”掩盖边界错误：

1. 内容分类：规则违规、广告/垃圾、攻击性或骚扰、事实性主张、观点、讽刺/反问、普通内容。
2. 核查状态：`verified`、`contradicted`、`unverified`、`not_checked`、`insufficient_context`、`not_applicable`。
3. 推荐动作：`keep`、`defer`、`review`；`block` 只表示进入人工审核的候选，不表示已经执行屏蔽。
4. 身份与可执行性：可靠 UID、hash-only、无身份、碰撞、卡片失败和会话失效分别记录；无可靠身份时预期必须是“不可执行”。

## 阶段 1：独立本地评测集

### 数据组成

- `policy_core`：人工合成的规则违规、广告、刷屏、骚扰和明显正常内容，覆盖短句、长句、表情、混合语言、错别字、反讽和上下文依赖样本。
- `fact_claims`：同一主题下的已证实、明确矛盾、缺少证据、时间过期、主体/范围歧义和语境不足样本；标签不把“模型不知道”当作“事实为假”。
- `context_pairs`：只有加入标题、前后句、评论对象或引用片段后才改变结论的成对样本，用来测量语境不足时是否正确延期。
- `identity_gate`：可靠 UID、仅 hash、多个候选、卡片不存在、网络失败、旧路由迟到等输入，预期动作固定为可执行/不可执行。
- `lifecycle_cases`：确认后立即关闭、hidden 暂停、恢复、撤销、换路由、换视频和重复点击，用于确认后台任务不改变内容判定。

每条样本至少包含稳定内部 ID、脱敏文本、平台/内容类型、标签、预期动作、标注理由、数据来源类别和数据集版本。内部 ID 不得编码真实账号或页面标识。样本正文不进入运行日志，报告只输出聚合数字和错误类别。

### 标注协议

- 两名独立标注者先分别给出 `claimType`、`verificationStatus`、`contextSufficiency`、`expectedAction` 和 `identityAction`。
- 分歧进入第三人仲裁；保留标签变更原因和协议版本，禁止事后为了让模型通过而改金标准。
- 先写“为什么不应屏蔽”，再写“为什么可进入人工审核”；事实证据不足默认 `defer`。
- 为讽刺、提问、引用他人、主观评价、转述和未完成句保留明确标签，避免把表面关键词当成规则违规。

### 数据切分与防泄漏

- 按主题、模板、改写族和作者语义簇切分 `dev`、`test`、`challenge`，同一语义族不能跨集合。
- `test` 只在评测版本冻结后使用；调 prompt 只能看 `dev`，不得用 test 错例反复调参。
- `challenge` 专门放模型常见误报、边界和身份竞态，发布前只读一次，结果进入版本记录。
- 每个数据集保存清单哈希、标注协议版本、构建时间、样本数量和删除/替换记录；不保存真实站点原始抓取包。

本轮实现：`test/fixtures/ai-eval-v1.json` 为人工合成/脱敏数据集，共 24 条，按 `dev=10`、`test=8`、`challenge=6` 切分；规范 JSON SHA-256 为 `4a7e2cc9403693c2ae3116ecc7f0ec985f65a47700c9a38dfb3a63527cfb84bc`。`node test/ai-eval.cjs --mode=mock` 的 `structure regression` 通过，报告明确标注为 mock-oracle，只验证 schema、指标引擎和安全门禁，不代表真实模型准确率。

## 阶段 2：可重复离线评测

每个候选运行至少三次：一次固定参数的重复性检查，以及两次独立运行用于发现随机性。每次报告必须绑定模型、prompt、网关、温度/采样参数、schema、超时、批次大小和评测集哈希。若模型不支持确定性参数，报告均值、标准差和最差运行，不只报告最好一次。

必须输出的指标：

- `policy` 分层 precision、recall、F1 和混淆矩阵；规则违规与普通内容分开统计。
- 事实类的 `defer precision`、`unverified false-block rate`、`contradicted recall`、语境不足延期率和“证据不足却给出肯定结论”的比例。
- 候选覆盖率、可解析响应率、schema 错误率、空响应率、拒答率和按内容类型分层的置信度分布。
- 身份安全指标：无身份执行率必须为 0；hash-only 被误写成 UID 的次数必须为 0；碰撞、卡片失败、超时、旧会话迟到写入次数必须为 0。
- 生命周期指标：确认到浮层关闭的 p50/p95、基础名单首次写入 p50/p95、后台完成/暂停/取消比例、重复任务数、跨会话落盘次数和撤销后残留键数。
- 资源指标：用户卡片缓存命中率、请求数、退避次数、失败率、批次耗时、网关耗时、估算 token/费用以及异常日志数量。

除点估计外，test 指标要给出样本数和置信区间。小样本不得写“准确率已证明”；只能写“当前样本观察”。必须与 `baseline-v0.53.1` 比较，任何 recall 提升都不能抵消 `unverified false-block rate` 或身份安全门禁的回归。

建议的初始放行门槛（实现前仍需用户确认）：

- 身份安全、跨会话写入和 hash→UID 猜测为零容忍门槛，任一失败直接阻断。
- `unverified`、`not_checked`、`insufficient_context` 的误阻断率不高于基线且目标为 0；出现正向矛盾证据才允许进入 `review`。
- 规则性违规的 recall 不能低于基线 5 个百分点以上；若提升 precision 需要牺牲 recall，必须明确记录取舍。
- 三次运行的关键指标波动不超过预设阈值；schema/error/timeout 率不能因模型切换而上升。
- 浮层即时关闭、基础写入、暂停/恢复、撤销和路由取消全部通过，不能用平均耗时掩盖单个竞态失败。

本轮实现：`test/ai-eval.cjs` 支持脱敏 prediction 记录，默认只运行 mock-oracle；连续 3 次运行保持数据集哈希 `4a7e2cc9403693c2ae3116ecc7f0ec985f65a47700c9a38dfb3a63527cfb84bc` 和 `gatePassed=true`，身份越权、schema 错误和未核查误阻断门禁均为零。`test/ai-fact-integration.cjs` 的 `structure regression` 覆盖默认关闭、canary 二次核查、受限矛盾来源进入人工审核、shadow 只观测不改变候选四条路径；与现有 AI screening、prompt/eval、内容 AI 和批次回归联跑无页面/控制台错误。

## 阶段 3：受控事实检索实现（默认关闭）

### 检索输入与来源

- 只对被模型标记为事实性主张且确实需要核查的候选发起检索；规则违规、观点、讽刺、普通内容和身份查询不进入检索。
- 默认先使用本地允许列表和用户明确配置的来源；公共搜索、开放网页抓取和不透明聚合站不作为第一实现。
- 来源按“官方/一手材料、原始数据或正式文档、可信二手报道、其他”分级；当前 broker 只保留配置来源 ID、来源等级、标题、发布日期、受限摘要和 verdict，不把原始域名/URL返回页面；若未来需要可追溯域名，必须先补隐私评审和对应回归。
- 查询前做最小化和脱敏：去除 UID、hash、页面 URL、用户名、Cookie、Token 和无关上下文；不把整页正文原样发到公共搜索。
- 检索返回“无结果、来源冲突、来源过期、来源不可访问、内容不足”时统一 `not_checked` 或 `insufficient_context`，回退 `defer`。

### 缓存、隐私与成本

- 缓存键只由脱敏后的规范化 claim 指纹、来源策略版本和语言组成；禁止以账号或页面 ID 为键。
- 缓存条目有 TTL、来源快照哈希和失效原因；来源变化、策略升级、用户撤回授权或隐私检查失败时可清理。
- 记录请求计数、状态、耗时和费用估计，不记录原始查询、原始响应或个人数据到 EventLog；调试材料必须是本地脱敏样本。
- 所有网络请求设置超时、最大响应大小、域名 allowlist、重试上限和全局熔断；失败不触发无限重试，不阻塞弹窗关闭和本地基础屏蔽。
- 检索证据只辅助模型输出 `verificationStatus` 和审核说明，不直接转成屏蔽键，也不增加 UID 可信度。

本轮实现：`gateway/scripts/fact-retrieval.cjs` 是 loopback-only 的本机 broker，默认端口 `4001`，来源必须来自本机配置的显式 allowlist；`gateway/fact-sources.example.json` 只提供占位示例，默认没有真实来源。broker 只接收 ordinal `c1...` 和脱敏 claim，拒绝未脱敏请求；来源响应即使没有 `Content-Length` 也受 256 KiB 上限约束，字段再做 URL、凭据、身份和长数字脱敏，只返回受限来源元数据，不返回原始 URL；无来源、冲突、过期或失败统一回退 `not_checked`。`node test/ai-retrieval.cjs` 的 `structure regression` 覆盖脱敏、来源拒绝、响应裁剪和无证据回退（RETRIEVAL-1..5）。

### 证据质量与冲突处理

- 结论必须绑定至少一个可追溯来源；单一低等级来源、来源之间冲突或时间敏感事实默认 `defer/review`。
- 只显示有限长度、脱敏、可定位的来源摘要，不在审核 UI 中复制整篇文章；来源不可访问时保留“曾命中但当前不可读”的状态而不是伪造确定性。
- 事实检索与政策违规分类分开打分；来源支持事实不代表该内容符合平台规范，事实矛盾也不代表可以绕过人工确认。

## 阶段 4：部署路线与回滚

1. `offline`：只跑本地评测集和脱敏 gateway mock，不改变用户页面或网络行为。入口条件是数据协议、指标脚本和安全用例评审完成。
2. `shadow`：在本机 loopback 内记录聚合结果，不展示检索结论、不改变候选、不写名单；观察至少一个完整版本窗口，比较基线和资源成本。
3. `canary`：仅对明确开启的本机实验配置展示“待核查/来源摘要”建议，仍然必须人工确认；不自动屏蔽、不扩大 UID 关联、不把来源写入用户反馈账本。
4. `gated release`：达到所有放行门槛后才进入正式版本；保留一键关闭检索、回退到 `not_checked/defer`、删除缓存和恢复 baseline prompt 的开关。
5. `post-release`：只看聚合错误、耗时、成本、误报反馈和回滚信号；成功同步保持安静，异常或需要用户处理时才提示。

当前 rollout 状态：offline、shadow、canary 均已由本地夹具验证；userscript 设置默认 `off`，`shadow` 不改变候选，`canary` 只允许有受限证据的事实性结果进入原有人工审核，任何模式都不自动写名单、不扩大 UID 关联。未配置真实来源 allowlist，公共搜索和线上模型精度观察记为 `blocked`。

真实站点证据：`real-site verified`，2026-09-10，隔离匿名只读会话，脱敏页面形式 `bilibili.com/video/...`；当前候选版本/构建为 `0.54.0` / `0.54.0-ai-eval-fact-gates`。普通探针观察到 50 条 AI 内容（作品 1、评论 3、弹幕 46），弹幕工具 77 个分组/46 个发送者、浮动弹幕 7 条；AI 后台探针实际产生 1 个弹幕候选，确认后审核浮层立即关闭、基础 hash 写入 1 次并生效，完成提示出现，最终键生效。该探针只写隔离内存存储，未触发平台官方写入。事实 broker 与线上模型精度没有真实来源/模型运行条件，仍为 `blocked`。

每一阶段都有独立的进入/退出记录。出现身份越权、公共网络越界、原始文本落日志、误阻断上升、来源无法追溯、成本失控或跨会话写入，立即关闭实验开关并回退到 v0.53.1 行为；不能等待下一版本修复。

## 实现前后的验收清单

- 先新增离线数据格式、生成器、标注协议和指标脚本，再接入任何真实模型或检索接口。
- 为脱敏、allowlist、超时、缓存 TTL、熔断、无来源回退、schema 错误和日志计数新增回归断言。
- 保留现有 AI screening、prompt/eval、quickblock、扩展桥和真实只读探针；新增探针只能点击脚本 UI，不能触发平台举报、官方拉黑、关注或发帖。
- 分别验证“没有引用/尚未核查”“明确矛盾证据”“规则违规”“身份缺失”“hash-only”和“撤销”六条路径。
- 发布前必须更新 README、版本 changelog、CURRENT、PLAN 和架构边界；证据继续只使用 `structure regression`、`real-site verified`、`blocked` 三类标签。
- 任何需要密钥、Cookie、`.env`、系统配置、数据库迁移或平台写入的步骤，另行停下请求明确授权；本计划不包含这些授权。
