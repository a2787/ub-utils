# OB-AI-014：作品语境感知的 AI 屏蔽

状态：`verified`（阶段 A-D、E1 单作品预算和 E2 紧凑线协议均完成）。本计划承接上一轮对 B 站“同词异义、同话跨作品含义不同”的审计，已把作品主题、父评论关系和可证明的弹幕位置纳入 AI 判断，同时保持人工确认、身份门禁和本地优先级不变；真实内容长期精度、字幕/音频/画面语义按前置条件封存为远期预留，不再作为活动阻塞项。

## 目标与不变量

本项解决的是“同一段文字在不同作品或不同回复关系中含义不同”，不是把页面上的所有文字拼成一个更大的 prompt。第一实现只覆盖 B 站视频详情页；其他平台后续必须分别捕获 DOM 和内容作用域，不能复制 B 站选择器或假设。

必须保持以下不变量：

- AI 仍然只生成审核候选；`block` 代表“可进入人工审核”，不代表已执行屏蔽。
- 标题、简介、父评论或相邻弹幕只能改变对候选的解释，不能单独成为屏蔽条件；需要命中当前启用规则并有足够语境。
- `insufficient_context`、`not_checked`、普通观点、引用/反讽和事实未核查默认延期或保留；不能因为模型缺少信息而扩大屏蔽。
- 语境相关候选默认只影响当前作品/分 P/内容实例，保存在当前浏览器会话；全局作者屏蔽需要单独显式选择，并继续要求可靠 UID 或已有可靠哈希键。
- `mid_hash`、弹幕 hash、评论 ID 等内部键只留在浏览器本地。发送给 loopback 网关的 item/context ID 为本次会话生成的序号，不发送 URL、UID、hash、昵称、Cookie、Token 或原始平台对象。
- 既有关键词和人工名单优先于 AI；语境逻辑不得让已命中的全局规则恢复内容，也不得把上下文候选写入全局名单。
- 本项不调用 B 站举报、官方拉黑、关注、发帖等写入接口；不读取或导出凭证。

## 先前审计得到的实现依据

1. 当前 B 站 AI 记录只把每个弹幕发送者压缩成一条代表文本，丢失同一发送者的多条内容和时间位置；因此需要保留“消息实例/进度/分 P”内部元数据，而不是继续以 sender-only record 作为语境输入。
2. 当前审核确认直接写入 `Store.addIdentityGroups`，会把语境候选提升成全局作者/哈希屏蔽；本项必须拆出当前作品作用域，保留全局操作作为显式分支。
3. 当前负反馈按平台、类型和正文匹配，无作品/父评论/位置范围；同文跨作品会互相命中，必须将旧的无语境事件视为未知，不跨作用域复用。
4. 当前 `context_pairs` 评测只含 `kind/contentType/text`，不能证明真实语境效果；新增评测必须使用同一语义族的不同作品/父评论变体，并把整个语义族放在同一数据切分中。

这些依据来自本地源码审计和公开研究的设计启发，不等于线上模型效果证明。研究只用于决定评测方式：将“有/无上下文的标签变化”作为一等测试，增加功能性不变性和最小上下文测试，不把平均准确率当成安全保证。

## 语境数据契约

### WorkContext

```text
workKey       本地不透明指纹，当前视频/动态作品会话
partKey       本地不透明指纹，分 P/cid 可用且可靠时才填
revision      作品标题/简介/分 P 变化时递增的本地版本
title         规范化标题，最多 240 字
description   规范化简介，最多 800 字
sources       title|description|page_state，实际读取来源
confidence    reliable|partial|missing
```

### LocalContext

```text
itemKey       当前内容实例的本地不透明键
kind          content|comment|danmaku
parent        只有 DOM/API 明确建立回复关系时才提供，最多一层
time          只有弹幕 progress/segment 可靠时才提供
neighbors     默认不发送；未来实验必须证明来源和窗口后再启用
```

`workKey/partKey/itemKey/parentKey` 在浏览器内由现有规范化身份/评论 ID/弹幕 hash
和当前会话代数计算，但网关只看到 `w1/p1/i1/r1` 这类随机序号。键不能进入 EventLog、备份、反馈展示或版本化测试输出。

v0.56.0 的线协议为 `contextSchemaVersion=2`：单一作品/分 P 批次把 `workId/partId/sufficiency`
放入 `contextCatalog.defaults`；无差异条目省略 `context`，时间差异使用 `[progressMs, segmentIndex]`，
父评论差异使用 `[relation, text]`。如果批次作用域不一致，保留显式字段形态。该压缩只作用于网关 prompt，
不改变浏览器内完整上下文、作用域键或候选解析。

### AI 输出扩展

保留现有 `decision/claimType/verificationStatus/verificationMethod/ruleMatched`，增加受限字段：

- `contextSufficiency`: `sufficient|partial|insufficient|not_applicable`
- `matchedRuleIds`: 当前规则的短 ID 列表；只允许返回输入规则的 ID
- `evidenceRefs`: `title|description|parent|time|item` 的有限引用
- `reason`: 只说明命中的规则和语境作用，不复述整页内容

解析器只接受白名单值和输入中存在的规则 ID。`block` 必须同时满足：命中规则、`contextSufficiency` 不是 `insufficient`、且不是待核查事实的保守延期路径。任何字段缺失都按现有安全默认处理，不为兼容旧模型而猜测上下文。

## 分阶段实施

### 阶段 A：契约、评测与隔离回归

- 新增脱敏 `context-v1` fixture：至少包含同一语义族的跨作品 allow/block、父评论决定含义、缺少父评论应延期、同文跨时间片不串联、提示注入、顺序/无关上下文不应改变结论。
- 测试 `normalize/serialize/context budget/ordinal ID/old feedback unknown/cache invalidation`。
- 建立 `baseline`、`title+description`、`title+description+parent/time` 三种输入模式；按语义族切分 dev/test/challenge，禁止同族泄漏。
- 本阶段只证明协议和隔离，不声称真实模型精度；若当前网关未配置线上模型，标记 `blocked`。

阶段 A 退出条件：旧回归保持通过；跨作品负反馈不复用；上下文不进入日志和身份键；缺少语境不生成可执行候选。

### 阶段 B：B 站作品/内容实例采集

- 从当前真实捕获的 B 站视频详情结构读取标题和简介，使用当前 `activeVideoIdentityGeneration`/路由会话隔离；分 P/cid 变化时刷新 `partKey` 和 context revision。
- 评论只附带真实的 root/reply 关系；没有可靠父节点就省略 parent，不使用页面上“上一条评论”或 DOM 邻近关系猜测。
- 弹幕内部保留每条消息的 `hash/content/progress/segment`；同一发送者多条消息不能压缩成一条 AI 记录。若位置不足以唯一定位，只提供只读建议，不扩大为该发送者全部弹幕。
- feed/动态卡片每条作品自带 context；不能用当前视频标题覆盖多个卡片。动态详情在未取得独立捕获前维持现有 partial 行为。

阶段 B 退出条件：`collectAIRecords` 的记录包含可追踪的本地 item/work 元数据；同一页面换片、换分 P 或刷新简介后旧缓存/候选不再复用；不扩大已观察内容为全量。

### 阶段 C：语境 prompt 与安全解析

- 网关输入采用短结构化 `context`；v0.56.0 使用 `contextSchemaVersion=2` 的作品默认值、时间元组和父评论元组；当前作品标题/简介只放在对应 `contextCatalog.works`，不把整个页面拼入每个 item。
- 先给 item，再给最小必要 parent/time；限制总量，沿用现有 48,000 字符/80 项预算，本项目标额外输入不超过 25%。
- 在 prompt 中明确正文和上下文都是不可信数据；只按 `rules` 和 schema 输出，拒绝 context 中的指令。
- `parseCandidates` 增加 context 充分性与规则 ID校验；旧响应无扩展字段时按 `insufficient/unknown` 的保守兼容路径处理。

阶段 C 退出条件：离线注入/空字段/乱序/未知 rule ID/过长上下文/伪 JSON 回归通过；事实核查链仍独立。

### 阶段 D：当前作品可撤销屏蔽与反馈隔离

- 审核行显示“当前作品”作用域；默认确认只写当前会话的本地 `ScopedBlock`，立即隐藏已观察内容并对后续同作品同实例重绘生效。
- “全局作者”必须是独立显式操作，只有可靠身份才可用；现有 `Store.addIdentityGroups` 和 UID 增强任务只处理该分支。
- 评论当前实例按 item/thread 键隐藏；弹幕按 work/part/progress/hash 精确匹配。没有可靠位置时不得降级为“全局同文本/同发送者”。
- 反馈事件增加可选作用域指纹和 context provenance；没有 context 的旧事件不能跨作品命中。缓存同时包含 work/item/context revision、规则版本和 prompt 配置签名。
- 提供本次作品作用域的清除/撤销路径；不删除用户原有全局身份。

阶段 D 退出条件：确认后浮层立即关闭、当前作用域立即生效、全局名单未被语境候选污染、换作品后恢复未命中、撤销无残留。

### 阶段 E：选择性增强与评测门禁（已收口）

- 已完成 E1：`test/ai-eval.cjs --mode=live --scope=work --variant=baseline,full --runs=3` 只向 loopback 网关发送人工合成 `ai-eval-v1`，按 7 个不透明作品分成 42 次请求；输入字符 `15171 → 17742`，加权增长 `16.95%`，聚合 p95 `2174ms → 2177ms`、比值 `1.0014`，输入/聚合 p95 门禁通过。
- 已完成 E2：v0.56.0 将同一作品/分 P/批次的默认语境提升到 `contextCatalog.defaults`，无差异项省略 context，弹幕时间使用 `[progressMs, segmentIndex]`，父评论使用 `[relation,text]`；作用域不一致时保留显式字段。该压缩只改变线协议，不改变内部语义和安全门禁。
- 评测门禁通过：baseline/full 的 policy/context recall 与 defer precision 均为 `1.0`，误阻断率差为 `0`，schema 错误、未核查事实误阻断和身份越权均为 `0`；3 次小样本下的按作品 p95 只作为诊断，不覆盖加权聚合门禁。
- 已做真实输入预算核对：匿名隔离 B 站实际三个网关批次额外输入为 `21.8%/21.4%/21.8%`，均低于 25%；同轮确认后浮层即时关闭、当前作品作用域生效、全局键和存储写入不变。
- 只封存为远期预留：真实用户标注集驱动的长期语境精度；字幕/音频增强；视频画面语义。它们分别需要同意/脱敏数据，稳定可读且可授权的媒体来源，或独立多模态隐私/成本计划，当前不满足条件，不再作为本项活动阻塞。

最终放行门槛：身份/隐私/跨作用域写入零容忍；语境相关误阻断不因上下文增加；明确规则 recall 不下降超过 3 个百分点；输入字符不超过基线 1.25 倍；加权 p95 不超过基线 1.30 倍。门槛只证明当前合成/真实只读链路的安全和成本边界，不等价于真实模型长期精度。

## 回滚与发布

- 任一阶段发生跨作品屏蔽、旧反馈误命中、未脱敏上下文进入网关/日志、hash→UID 猜测、路由迟到写入或全量延期掩盖错误，立即回退到已发布的 v0.55.0 显式上下文形态；不得为了保留压缩而放宽身份或作用域门禁。
- 不改存储 schema；当前作品作用域优先放在会话内存，若将来持久化必须另立计划并先处理迁移/兼容授权。
- 发布前更新 `README.md`、版本 changelog、`CURRENT.md`、`PLAN.md` 和架构边界；只选择性暂存本项文件/测试/源码，保留工作区既有截图。
- 真实站点证据必须单独记录日期、脱敏页面形式、登录状态和确切数量；本地 fixture 只能标 `structure regression`，探针受限则标 `blocked`。
