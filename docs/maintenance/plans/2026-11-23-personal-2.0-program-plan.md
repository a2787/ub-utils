# OmniBlock Personal 2.0 实施计划（一键屏蔽、可见失败、可持续维护）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 OmniBlock 从“需要记住、需要确认、失败不可见”的工具箱，改成“看到内容 → 一次点击 → 立即隐藏 → 10 秒内可撤销”的个人日用工具，同时不改变用户明确要求的收起态控制坞设计。

**Architecture:** 保留单文件 userscript 与现有身份解析/存储/隐藏链路，只在 `showConfirm` 这个所有人工屏蔽入口的统一收口处抽出 `commitBlock`；快捷入口与作者入口默认直接提交，批量/弹幕/UID 候选继续确认。新增 `Health` 聚合层与日志硬上限，让存储/适配器失败可见；设置只做减法和接线，不重做信息架构。测试以现有夹具为主，新增“无确认/撤销/健康/代码健康”断言。

**Tech Stack:** Tampermonkey userscript（ES2020）、GM_* 存储、Playwright-core 夹具、Node 标准库；不新增运行时依赖。

**Spec:** 本文 §2（目标形态与设计约束）。

## Global Constraints

- 保留用户明确要求的外观：右下角控制坞默认收起、齿轮 0.55 透明度、悬停展开；不重做视觉。
- 不新增新手引导、平台级主开关、全局快捷键（2026-10-27 计划归档中用户已明确否决，见 `docs/maintenance/plans/2026-10-27-plan-closure.md:139`）。
- 保留低调脚本名 `本地内容过滤增强`、`@namespace`、`@updateURL`、`@downloadURL`；不因品牌一致性改这些字段。
- 所有入口仍不调用平台举报/官方拉黑/关注/发帖；身份不可靠时不生成可执行入口。
- AI 只能提出候选，必须人工确认；AI 默认关闭，不进入核心路径。
- 不改存储 schema：保留 `omniblock:data:v1`、`omniblock:backup:v1`、`omniblock:recent-actions:v1`、`omniblock:sync-local:v1`；任何升级前先导出名单。
- 证据标签只用 `real-site verified`、`structure regression`、`blocked`；夹具通过不得写成真站可用。
- 登录态真实站点探针必须由用户对本轮显式授权；批准本计划不等于授权登录态探针。
- 用户可见行为变化必须提高 `@version`，同步 README、根 CHANGELOG、`docs/changelog/vX.Y.Z.md`、`docs/maintenance/CURRENT.md`。
- Phase 1-4 的 commit 只本地累积、不发布；Phase 5 统一 bump `0.64.0` 并完成全部回写。若中途发布，该阶段必须单独 bump 并完成全部回写，不能等 Phase 5 补。
- 每个修改 `omniblock.user.js` 的 commit 前，用 `sha256sum omniblock.user.js`（或 Node crypto）计算并写入 `docs/maintenance/CURRENT.md` 的“当前候选源码 SHA-256”，与 userscript 同批 `git add`/commit；commit 后再跑一次 `docs-check` 核对。CURRENT 的“最近验证的源码快照”仍保持最后一个真站验证提交，不改成未验证提交。不能留脏文件跨轮。
- 每次代码改动至少运行 `node --check omniblock.user.js` 与 `git diff --check`；文档改动运行 `node test/docs-check.cjs` 与 `git diff --check`。
- 不新增 npm 依赖；统计/门禁用 Node 标准库。
- 工具 worktree/缓存目录（如 `.qoder/`）不得提交；验证结束后清理或加入 `.gitignore`，避免污染 `git status`。

## §2 目标形态与设计约束

### 2.1 北极星

在支持的平台上，对任何已可靠识别的内容条目：

1. 作者入口或快捷入口一次点击；
2. 当前内容立即按既有策略隐藏（评论零占位；帖子折叠/消失）；
3. 名单写入本地，后续同身份内容自动隐藏；
4. 10 秒内可点 toast 撤销；错过窗口可从“撤销上一次”或“最近操作”恢复；
5. 不需要打开设置、不需要配置 AI、不需要进入批量弹窗。

### 2.2 两条主路径

- **作者入口（帖子/视频/动态）**：复用现有 `.ob-weibo-author-block`、`.ob-bili-author-block` 常驻入口；点击直接提交，不再弹确认。
- **快捷入口（评论/原生菜单）**：复用 `.ob-quick`；点击直接提交；弹幕、批量、UID 候选仍保留确认。
- **列表/关注流**：B站作者门户只覆盖当前详情页（`videoAuthorInfo` → `opusAuthorInfo` 单选），关注流/列表卡片的作者卡走原生菜单的 `.ob-quick`；Task 1.4 的悬停 chip 只在走查证明列表页仍需多步时扩展过去。

### 2.3 确认策略

| actionType | 默认行为 | 理由 |
|---|---|---|
| `quick` | 直接提交 + 10s 撤销 | 单身份、可撤销、最高频 |
| `author` | 直接提交 + 10s 撤销 | 单身份、入口常驻、可撤销 |
| `bulk` / 未标记 | 保留确认气泡 | 多身份，误操作代价高 |
| `danmaku` | 保留确认气泡 | 弹幕身份/UID 有碰撞风险 |
| UID 候选确认 | 保留确认气泡 | 必须人工选择唯一候选 |

`.ob-quick` 既可能是评论 quick，也可能是 B站弹幕 dmhash；`actionType` 必须由身份键派生，不能由 DOM 类名猜。

设置新增 `quickBlockNoConfirm`，默认 `true`；关闭后所有入口恢复确认气泡。

### 2.4 平台范围

- Phase 1 真站门禁默认覆盖 **B站 + 微博**（作者入口与快捷入口最完整、已有真站证据）。
- 知乎/贴吧/抖音保持代码可用，Phase 1 只做结构回归；X 保持现状（公开验证仍是 `blocked`）。
- 如果用户指定其他日用平台，交换真站门禁平台即可，不改核心实现。

### 2.5 成功度量

- 首次屏蔽：安装后从“看到内容”到“隐藏”≤2 个用户动作（不含安装）。
- 撤销：按设置的撤销停留时长（默认 10 秒，可配 5–30 秒）内 1 次点击恢复；过期后“撤销上一次” 1 次恢复。
- 可见失败：存储降级/写入失败在设置诊断区或下一次主动屏蔽 toast 中可见（用户动作后 1 秒内）；不再有新增空 catch。
- 日志：总量硬上限 2 MiB，7 天保留，单日 5 千条；不影响名单/备份/撤销。
- 证据：核心路径至少 1 个主平台 `real-site verified`；未授权则全轮最高只能记 `structure regression` 或 `blocked`。

- [ ] **Step 2：实现 Health**

```js
const Health = (function () {
  const MAX_ERRORS = 20;
  const RECENT_WINDOW_MS = 5 * 60 * 1000;
  const errors = [];
  let reportFailures = 0;
  function report(scope, error, data) {
    const entry = {
      at: Date.now(),
      scope: String(scope || 'unknown').slice(0, 64),
      name: String(error && error.name || 'Error').slice(0, 48),
      message: String(error && error.message || error || '').slice(0, 240),
    };
    errors.push(entry);
    if (errors.length > MAX_ERRORS) errors.shift();
    try { EventLog.recordError('health.' + entry.scope, error, data); } catch (e) { reportFailures++; }
  }
  function snapshot() {
    const storage = Store.storageStatus();
    const logs = EventLog.status();
    const backup = Store.backupStatus ? Store.backupStatus() : null;
    const degraded = !!(storage && storage.degraded);
    const recentErrors = errors.filter((e) => Date.now() - e.at <= RECENT_WINDOW_MS);
    return { ok: !degraded && !recentErrors.length, storage, logs, backup, errors: errors.slice(), recentErrors, reportFailures };
  }
  return { report, snapshot };
})();
```

## §10 风险、回滚与停止条件

| 风险 | 触发 | 缓解 | 回滚 |
|---|---|---|---|
| 无确认导致误屏蔽 | 用户误点作者/快捷入口 | 默认 10 秒（可配）toast + “撤销上一次” + 最近操作 20 条 | 设置关闭 `quickBlockNoConfirm` |
| toast 单例丢失撤销 | 连续快速屏蔽 | `RecentActions.undoLast` + 最近操作列表 | 回到确认模式 |
| 虚拟列表复用导致错屏蔽 | 微博/抖音节点回收 | 点击时重新识别 + 快照兜底 + 重扫清理 | 移除 chip，仅保留原生菜单入口 |
| 备份读取失败被覆盖 | 损坏的 backup 键 | `corrupted` 时跳过写 + Health 记录 | 从导出 JSON 恢复 |
| 日志瘦身丢诊断 | 旧日志被裁剪 | 保留 7 天/2MiB；先导出；错误仍记录 | 调回常量 |
| 文档拆分断链/超预算 | README 拆分 | docs-check + 知识树路由 | 恢复 README 原段落 |
| 更新地址被改导致旧版无法升级 | 修改 `@updateURL`/`@namespace` | 明确禁止修改这些字段 | 恢复原值 |
| 真站探针仍死等 `#ob-confirm` | 默认直提后探针超时假失败 | 先完成 Task 1.2b 的 confirm-or-direct helper；批量/弹幕仍要求 confirm | 恢复默认确认 |
| 列表卡片身份不可解析 | chip 不出现、原生菜单也无入口 | 记 `blocked`；默认停止发布；只有用户当前轮明确接受且 README/changelog 标注限制后才可带限制发布 | 回退详情页/原生菜单 |

**停止条件：**
- 身份解析不可靠却出现可执行入口 → 立即停止并修复。
- 任何平台写入控件被触发 → 立即停止并回滚。
