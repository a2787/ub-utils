# 平台适配细节与验证说明

> 本文件承载从 README 拆出的逐平台实现细节、入口规则、限制与验证说明。所有者：日常维护轮；与
> `docs/maintenance/CURRENT.md` 冲突时以 CURRENT 为准。预算见 `test/docs-check.cjs`，接近先合并去重。

## 总则

- 只有能从条目自身可靠解析出规范身份时，脚本才隐藏内容或提供可执行拉黑入口；解析不到就保持原样。评论、
  帖子/动态、回答/文章/想法/专栏、搜索结果和作品列表的实际覆盖，以文末验证表和
  [当前维护状态](../maintenance/CURRENT.md) 的证据标签为准；懒加载或虚拟列表只代表当前已观察到的范围。
- 快捷入口复用当前平台适配器的身份提取结果并统一生成规范身份 key；入口靠**菜单文字 + 可验证身份上下文**
  匹配，没有可靠身份时不注入，既避免「拉了黑却没隐藏」的孤儿 key，也不放点击后报错的入口。
- 已识别的评论和弹幕无提示、零占位消失，不显示恢复条/「内容已屏蔽」文字、不留空行，下一条直接补位；
  其他内容按设置折叠成灰条（默认，可追溯）或消失。开关即时生效，关闭后当前页立即恢复、无需刷新。
- 设置面板两个开关：`本地拉黑入口` 控制平台原生菜单旁的快捷入口和 B站弹幕工具；`批量拉黑入口` 控制
  页面/弹幕管理器及其勾选批量按钮。抖音视频、微博帖子和 B 站动态详情页另有「🚫 屏蔽作品」入口：只处理
  当前作品作用域内可靠识别到的作者、主评论、子评论和弹幕发送者，先显示收集计数和「部分」警告再由用户
  确认；撤销只删除这次新增的身份。
- 触控设备（coarse pointer/无 hover）：右下角页面级「内容屏蔽/弹幕屏蔽」按钮保持可见，无需先悬停齿轮；
  面板、管理器、确认框和输入控件使用适合手指的触控目标，列表可滑动；桌面仍悬停展开、空闲收起。播放器内
  不接收指针事件的浮动弹幕采用「两次点按」：先点弹幕文字显示自有「🚫 拉黑」按钮再点它；同文案无法唯一
  对应可靠身份时不显示可执行入口。平台原生菜单仍由用户自己点按打开，OmniBlock 只在其中加本地按钮。
- 批量拉黑把每位用户保存为独立人物记录，撤销只删本次新增身份；可在设置里关闭。

## 各平台身份填写说明

| 平台 | 在设置里选 | 填什么 |
|---|---|---|
| B站 | B站 uid | 数字，如 `2233`（主页 URL `space.bilibili.com/2233`） |
| 微博 | 微博 uid | 数字，如 `1234567890` |
| 知乎 | 知乎 token | 个人页 URL `zhihu.com/people/这里` 的 slug |
| 贴吧 | 贴吧 uid | 旧版楼层 `data-field` 中的数字 `user_id`；新版详情评论使用已捕获的 Vue `userInfo.id` 数字值（首页 `.thread-card` 暂不支持） |
| X | X handle | 不带 @ 的用户名，如 `elonmusk` |
| 抖音 | 抖音 sec_uid | `MS4wLjAB...` 那串（作者主页 URL 里） |

## B站

**评论与楼中楼**：`bili-comment-menu` 内在「加入黑名单」或评论菜单「举报」（真站可能显示为「硬核会员举报」）
锚点后插入「🚫 本地拉黑」。根评论和真实 `bili-comment-reply-renderer` 楼中楼各用自己 UID；子评论点真实
三点菜单后触发补扫并插入本地入口；屏蔽楼中楼只让对应回复无占位消失，不隐藏整条根线程。主评论「🧵 屏蔽
回复」（完整语义在 title/aria-label「屏蔽该楼回复」）按接口 `page.num`、实际 `page.size` 和 `page.count`
读取该楼后续子评论页并与当前记录合并；接口失败、提前空页或达安全分页上限时明确提示「部分」，不把当前页
冒充完整楼层。评论管理器与 AI 候选优先取 `bili-rich-text`，排除点赞、回复、举报等同级操作组件和菜单文字；
正文自身出现同名词时保留。

**内容作者**：视频页作者名旁、动态详情页作者模块旁显示「本地拉黑作者」，经独立门户贴近作者行，不插入 B站
Vue 管理的正文节点。视频作者用空间链接 UID，动态作者用页面作者状态中的可靠 mid，身份不可解析时不注入。

**弹幕数据与身份**：在页面拿到数据前拦截 `seg.so` / `list.so` 弹幕段，错过首段时按当前视频 `cid` 主动只读
读取一次；手写轻量 protobuf 解析 `progress`、`mid_hash`、内容。检测到 PAKKU 时只桥接其公开 XHR 回调，不
覆盖普通评论、图片和视频分片请求；即使首段请求被接管，右下角入口也不消失，会用当前 `cid` 只读兜底。普通
弹幕段不提供昵称/UID，未触发目标屏蔽前名单默认显示 `bili:dmhash:<hash>`；`bili:uid:N` 经 CRC32 正向映射
到弹幕，已屏蔽评论的 UID 同样映射。UID 候选反查只在用户点击 `UID?`、执行单条/批量/悬浮/原生列表屏蔽或
确认 AI 弹幕候选时，才初始化约 1 MB 本地反查表、按 PAKKU 同类算法反查 1–10 位数字候选并匿名请求 B站用户
卡片接口剔除不存在账号；初始加载不全量反查。唯一且完整校验的候选同时保存昵称、hash 与 UID；碰撞、多候选、
失败或校验不完整时只保存 hash；`bili:dmhash` 永不伪装成已知 UID，未确认候选不会成为身份键，也不改写
`view` 元数据响应。v0.14.0 新增的 `api.bilibili.com` 连接权限只在主动查询候选时使用；请求匿名、不带登录
Cookie、不发送黑名单或浏览数据。AI 弹幕确认后审核弹窗立即关闭，基础 hash/已有 UID 先写入本地名单，页面
右下显示后台进度和撤销入口；UID 关联由最多 2 个并发后台任务补充，页面隐藏时暂停，停用、换路由、换视频或
撤销取消旧任务；卡片成功结果只在有界 TTL/LRU 缓存内复用，失败按退避重试。

**弹幕管理器**（右下角「内容屏蔽（评论/弹幕/AI/关键词）」内）：暂无弹幕数据时仍保留评论、AI、关键词标签，
弹幕标签在管理器可用时出现，数据未就绪时显示 `(0)` 和「重新读取」。打开后按文案分组显示发送者数：单击或
勾选批量屏蔽组内全部未屏蔽发送者并按 `mid_hash` 过滤；已屏蔽组灰色保留、可「取消屏蔽」；勾选多组展开去重。
每组旁 `UID?` 打开候选列表人工核对。只按 hash 屏蔽时评论需另行屏蔽，同 hash 后续弹幕继续过滤。自动规则
命中的组提供「恢复并例外」：按当前可靠 hash（及已确认 UID）保存例外并取消当前屏蔽，不关闭规则、不影响
其他发送者；多发送者无法逐一对应时按安全边界处理，以管理器可靠身份为准。**右侧原生弹幕列表**按行显示时间
读取对应 6 分钟数据段：唯一发送者显示「本地拉黑」，同文案多发送者显示「本地拉黑全部(N)」，未读取或未匹配
行显示禁用状态、不伪造身份；只展示弹幕正文，不拼接操作按钮文字。**播放器悬浮弹幕**：弹幕层写死
`pointer-events: none`，脚本按指针坐标判断指向哪条，不依赖网站是否弹出原生操作条；悬停弹幕旁浮出「🚫 拉黑
该弹幕发送者」并跟随移动，点击按需尝试 hash→UID 关联；仅当文案唯一对应一个 `mid_hash` 时出现，多发送者
改由右下角工具分组批量。已登录且网站弹出自带弹幕「举报」菜单时，脚本在该项目旁统一显示「🚫 本地拉黑」
并复用同一身份。

**批量**：视频页「🚫 拉黑已加载评论作者(N)」先弹范围面板：「仅当前已加载」或「加载全部评论与子回复」
（只读分页抓取公开评论接口，含未展开楼中楼作者，任一页失败提示「部分分页未取全」不伪装完整）；可按
「晚于该时间点」筛选（最近 1/6/24 小时、3/7 天或自定义），缺可靠时间的记录跳过。统计按 UID 去重，不把
右侧推荐视频卡误算为用户；原生举报、登录等弹窗打开时浮层隐藏，避免出现无意义的 `(0)`。

## 微博

**评论入口**：详情页和用户主页帖子内已加载的每条评论操作区常驻「本地拉黑」，用该行自己的 UID；根评论与
楼中楼都覆盖（真站结构 `.item1 > .item1in > .con1 > .info > .opt` 和 `.item2 > .con2 > .info > .opt`），
兼容 `node-type="reply_list"` / `.list_ul` / `.WB_reply` 旧结构。「共 N 条回复」弹窗中根评论与回复行各自
解析身份挂载入口；被隐藏行的包装层同步压成零高度收掉，不留空白。回复对象或 `@提及` 不会被当作评论作者；
展开行没有作者身份，不出现入口。

**帖子作者**：正文作者行和旧版信息流卡片作者名旁显示「本地拉黑作者」，用帖子作者自己的 UID；无可靠作者
链接时不注入。

**虚拟列表补位**：`vue-recycle-scroller` 下补位移动虚拟行的直接内容层，不改写平台控制回收的外层
`transform`，评论连续上移且不触发回收器频闪。平台把 spacer 恢复为原始基线时脚本接受该基线、不争夺同一
`style`；撤销时恢复内容层、列表和包装层状态。回收器按不同顺序复用物理行时，按行当前 `translateY` 的空间
顺序累计隐藏高度，避免重叠或空白；该修复只作用于已确认的详情页虚拟列表，超大或无效位置仍走原有安全路径；
只有确认虚拟行自身只包含被隐藏评论时才补位。被包裹的 `.item1` 遇异常超大 `transform` 按实际相邻行高度
重建补位；顶层评论直接包在 `wbpro-list > item1` 时同样用内容层补位。`opacity:0` 非活动行保留平台回收位置，
变为活动行后再补位；登录态首轮渲染的临时超大行高不会被缓存为真实评论高度。没有本地屏蔽行时不做整列表
布局扫描；已有补位工作的行或结构变化只在同批次观察回调内协调，spacer 回写只记录基线，避免页面被拖慢。
某些版本回收器可能保留少量末尾可滚动余量，但评论中间空洞由内容层补位消除。

**页内嵌套与无限流**：用户主页帖子内页内评论展开后，嵌套在帖子回收行内的 `wbpro-list` 评论按普通评论容器
处理，只折叠自身：不把整条帖子误当评论虚拟行、不为隐藏评论移动帖子本身或下方帖子、不接管外层帖子回收行。
热门/推荐等无限流帖子卡片由微博回收器管理；作者「本地拉黑作者」入口挂在独立页面门户，按作者链接视口位置
定位，不插入 `article/header` 布局树、不改写回收行高度或 spacer；拉黑整条帖子时卡片压成零高度，下一条
从原位补上；卡内预览评论仍按普通嵌套评论处理，不误当成详情页顶层评论列表。

**批量**：左下角「🚫 拉黑已加载微博/评论作者(N)」：详情页同时统计发帖人、已加载评论和已展开楼中楼回复，
按 UID 去重；未加载评论不虚构进计数。评论详情侧栏即使带 `Modal` 外层 class，只要实际承载评论，批量入口
仍显示。点赞/转发/粉丝等用户列表弹窗中只要实际列出可解析身份的用户链接，头部出现「🚫 拉黑全部(N)」，
仅一位用户时也可用；无可枚举列表时不虚构入口；弹窗复用后清掉旧按钮再统计。

## 抖音

**视频弹幕**：带 `data-danmaku-user-id` 的弹幕按 uid 隐藏。弹幕层写死 `pointer-events: none` 但节点自身
可接收鼠标事件：悬停弹幕时，文字左侧略有重叠处浮出「🚫 拉黑」按钮（挂进弹幕节点内）并跟随移动；点击按
`data-danmaku-user-id` 保存 `douyin:uid`，确认即本地拉黑，该弹幕和同发送者后续弹幕零占位消失。
`data-is-danmu-author="true"` 的作者弹幕额外映射当前视频作者 sec_uid，屏蔽作者本人时作者弹幕一并消失。
没有身份属性的弹幕不显示按钮、不会被误隐藏。

**弹幕管理器**：视频页右下角与齿轮同列（从下到上：设置、弹幕、评论）。「🚫 抖音弹幕屏蔽(N)」列出当前视频
已观察且带可靠 `data-danmaku-user-id` 的发送者，同发送者只占一行，支持搜索、全选、批量屏蔽。已屏蔽者
灰色保留、可「取消屏蔽」，不会被全选或批量再次选中；自动规则命中行提供「恢复并例外」，恢复后自动规则跳过
该发送者，例外可在设置「恢复规则」删除。「尽量加载弹幕」暂停并逐点扫描播放器时间轴触发懒加载，结束恢复
原播放位置与状态；扫描中关闭管理器立即取消并恢复播放头；不能保证无未渲染或已回收的弹幕。
精选/推荐流换视频时用当前播放器视频标识隔离观察缓存并终止旧视频扫描；未加载、无身份属性或未出现的弹幕
不会被猜测进来。按钮和弹窗只在视频页且「批量拉黑入口」开启时显示。

**评论**：「三个点」菜单里 portal/tooltip「举报评论」旁增加「🚫 本地拉黑」：即使菜单项是 portal 下
`role="tooltip"` 普通文本，也复用刚打开的评论上下文识别作者；只对「举报评论」叶子项注入，避免同一提示层
重复按钮；无法可靠解析 sec_uid 时不注入。右下角「🚫 抖音评论屏蔽(N)」管理器自动尝试展开带明确「展开/查看/
更多/共 N 条回复」语义的子评论入口，支持搜索、「尽量加载评论」只读滚动评论容器触发懒加载，再勾选或全选
批量屏蔽；不调用平台私有接口，列表以页面实际加载结果为准；平台回收、未加载或无明确展开控件的评论不会被
猜测成「全部」。

**推荐流**：刷到被屏蔽作者 → 视觉遮罩 + 自动切下一条，是全脚本唯一的「模拟操作」，带四道安全阀：① 仅
命中黑名单时触发；② 同一视频只切一次，复用节点展示新视频时重新判断；③ 200–600ms 随机延迟，执行前再次
确认当前视频和作者仍命中；④ 连续跳过上限（默认 6 次，`0` 为不限制）超限即停在遮罩。设置可一键降级为纯
遮罩。**绝不写 `media.muted`** 静音被跳过视频——抖音把静音当全局偏好，写它会污染正常刷视频的静音状态
（Pynseq 踩过的坑，已规避），改用视觉遮罩。
