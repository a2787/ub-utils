# OmniBlock v0.51.1

## B站新增内容累计增量 AI 分析

日期：2026-09-08
状态：提交 `910d2def9cb445273ebdc73472ec332d5043eafe` 已推送到 `origin/master`，未创建 tag/Release；当前公开版本仍为 v0.46.2。
构建：`0.51.1-content-ai-incremental`
计划：`OB-AI-003`

## 用户可见变化

- B站首轮自动分析完成后，滚动评论、展开楼中楼而出现的新评论，会按现有稳定记录 ID 只触发新内容的有界 AI 增量分析；旧评论不会再次发送。
- B站后续读取 `seg.so` 弹幕数据段时，新进入当前视频会话的弹幕发送者也会触发同一套增量分析，不再只更新弹幕管理器计数。
- AI 状态中的“已分析数量”改为当前页面累计已分析记录数；增量运行期间仍保留“本次新增记录”用于说明 token 消耗范围。
- 保留每个网关请求最多 80 条和总文本预算限制；本版本没有扩大单批上限，也没有自动滚动或展开页面。

## 验证证据

- `structure regression`：人工合成 B站 Shadow DOM/弹幕数据段夹具中，`node test/ai-screening.cjs` 18 项断言通过；评论滚动/点击增量只发送新记录，弹幕数据段触发只含新弹幕的请求，累计 `analyzed` 与当前 `records` 一致；无页面错误和控制台错误。`node --check omniblock.user.js` 通过。
- `real-site verified`：2026-09-08 专用 Chrome 持久化开发扩展，B站只读视频页（登录状态未判定，页面形式 `bilibili.com/video/...`）bridge 为 `ready`；首轮 224 条弹幕完成 `224/224`，滚动到评论区后为 `247/247`，展开楼中楼后为 `273/273`，期间每次 AI 事件只包含新增记录，旧内容未重复发送，页面错误 0。
- `blocked`：根评论分页仍为 partial，当前样本不能推导全量；登录态未判定，本轮未运行需要用户授权的登录态探针。

## 实现与边界

- 新增非 DOM `PageContentSignals`，仅广播平台和内容类型；B站弹幕 protobuf 解析确认出现新稳定记录后发送信号，滚动/展开楼中楼会低频重扫新增开放 ShadowRoot，AI 层继续使用现有本地关键词/名单过滤和稳定哈希去重。
- 自动运行期间到达的多个变化会合并到当前运行结束后的下一次延迟任务；不新增常驻 MutationObserver、无限重试或平台写入。
