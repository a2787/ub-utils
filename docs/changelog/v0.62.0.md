# OmniBlock v0.62.0 - 已屏蔽内容样本库与规则提炼

日期：2026-10-27。计划项：OB-RULE-004（见 [PLAN](../maintenance/PLAN.md)）。状态：本地候选，未发布（v0.59.0 仍为最新公开版本；v0.60.0~v0.62.0 在本地队列）。

## 背景

v0.59.0 把关键词/正则规则补齐为可运营的形态后，用户提出把"已经拉黑过的内容"变成免费规则的原料：
逐条手写关键词难以覆盖新话术，而每次人工确认拉黑的内容本身就是高质量的过滤样本。本版本把这条链路
落成"样本库 → 一键转关键词 / AI 归纳候选 → 人工确认写入"（OB-RULE-004），全程不消耗 AI 配额的本地
路径优先，AI 归纳是可选增强且必须二次确认。

## 用户可见变化

- **已屏蔽内容样本库**：每次你在确认气泡/批量确认/作品确认/B站弹幕确认/AI 审核确认中确认拉黑时，
  该条内容正文（规范化、截断 240 字）会进入本机样本库，按 B站/抖音分桶，每平台 LRU 上限 200 条
  （独立 GM 键 `omniblock:rule-samples:v1`）。样本仅保存在本机：不进入账户同步、名单导出、备份或事件日志。
  关键词自动规则写入、后台 UID 增强这类没有逐条人工确认的路径**不**产生样本。
- **样本转关键词（免费路径）**：关键词面板（「内容屏蔽」弹窗的关键词屏蔽标签或设置面板的规则管理入口）
  新增可折叠的「已屏蔽内容样本」区：显示最近 50 条样本（正文 + 相对时间），支持逐条「转为关键词」、
  勾选后「把选中转为关键词」「刷新」「清空样本」。写入走 `DanmakuRules.add` 的完整校验（去重、单平台
  上限 64 条），结果以「已新增 X 条规则；Y 条重复/无效被跳过」提示；转换不会删除样本。
- **AI 归纳提炼规则（需二次确认）**：样本区新增「AI 归纳提炼规则」——把该平台最近最多 100 条样本正文
  发给你已配置的 AI provider，请求只输出受约束的候选关键词/正则（关键词 ≤10 条、正则 ≤6 条、模式 ≤80 字符、
  明确要求可泛化模式而非照抄样本）。候选只进入人工确认列表：关键词默认勾选、正则默认不勾选，
  点「把选中加入规则」后才经 `DanmakuRules.add` 全量校验写入；重复、超限、危险正则（如 `(a+)+`）在写入时
  被拒并显示原因。provider/模型/Key 未配置时按钮禁用并说明原因；请求失败给出可读错误且不写入任何规则。
  归纳是独立的一次性直连请求（与手动分析同一通道与瞬态重试语义），不进入分析管线、不影响自动分析；
  请求正文只包含样本文本数组——没有身份键、URL、Cookie 或页面元数据。
- 采样永不阻断拉黑：样本记录全程容错，失败只记一条无正文的事件日志。

## 不变边界

- 不自动写入任何规则：所有写入（样本转关键词、AI 候选）都需要人工勾选 + 点击确认按钮。
- 不调用平台官方拉黑/举报/关注/发帖；样本库不进入账户同步；身份键规范不变。
- 样本与归纳候选仅 B站/抖音（与规则引擎同范围）；其他平台需先真站捕获结构。

## 已知限制与下一步

- 快捷确认的样本按入口锚点回溯正文（与"误屏蔽反馈"同一机制）：个别入口（如 B站弹幕工具内的多候选人工
  核对确认）锚点不在内容容器内时不产生样本；批量/弹幕/作品/AI 审核提交点按列表正文记录，不依赖锚点。
- AI 归纳候选只缓存在内存（切换面板/刷新页面后消失），属刻意设计：候选不持久化，重新归纳即可恢复。
- 样本只存正文文本，不含作者昵称或身份键；因此样本无法回答"是谁发的"，只用于内容模式挖掘。
- 关键词自动规则命中写入、后台 UID 增强不产生样本（没有逐条人工确认），边界同步写进了样本区说明文案。
