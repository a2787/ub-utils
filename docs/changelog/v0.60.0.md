# OmniBlock v0.60.0 - 设置面板信息架构与操作一致性

日期：2026-10-27。计划项：OB-UI-001（见 [PLAN](../maintenance/PLAN.md)）。状态：本地候选，未发布——未 push、未创建 tag/Release；候选构建 `0.60.0-ui-settings-ia`。

## 背景

v0.59.0 及之前，设置面板是单列长滚动：无分组导航，「反馈与日志」排在最前，核心的屏蔽与名单操作要滚动寻找；名单（点击删除）只能逐行浏览，记录多时无法定位；撤销 toast 固定 5 秒，来不及点撤销；退出同步账户、清空日志、恢复快照等关键路径混用原生 `window.confirm/alert` 与自建 UI。本版本收敛这批操作体验问题（OB-UI-001）。

## 用户可见变化

- **分组导航**：面板顶部新增一行锚点按钮——「屏蔽与名单 / 规则 / 备份与同步 / 更新与关于 / 日志诊断」，点击滚动到对应分组（scrollIntoView）；分组顺序即阅读顺序，日志诊断 LAST。仍是同一个 `#ob-panel` 单列弹窗，不是标签页重写。
- **名单搜索/筛选**：名单（点击删除）上方新增搜索框（按备注、身份键子串匹配，不区分大小写）、平台筛选下拉（全部/B站/微博/知乎/贴吧/X/抖音/跨平台/其他）与「显示 X / 共 Y」计数行；实时过滤，空结果给出可读空态（名单为空 / 没有匹配的记录）。筛选只影响显示，不改变存储与平台分组顺序。
- **撤销窗口可配置**：新增设置 `undoToastSeconds`（默认 10 秒，`sanitizeSettings` 收敛到 5–30；随设置快照同步）。「屏蔽与名单」分组提供「撤销确认停留」数字输入；撤销 toast 的自动关闭时长按该设置计算。
- **最近本地屏蔽操作**：确认拉黑（快捷/批量/作品/弹幕/AI 确认）后，操作记入「屏蔽与名单」分组的「最近本地屏蔽操作」列表——每条显示时间、类型（快捷拉黑/批量拉黑/作品屏蔽/弹幕拉黑/AI 确认）、平台与新增身份数，并提供「撤销」按钮；撤销走与撤销 toast 完全相同的 `Store.removeIdentities` + 扫描器重排路径，成功后该条记录移除。环形上限 20 条，独立 GM 键 `omniblock:recent-actions:v1`，只存时间/类型/计数/短标签/身份键（这些本就存在于本地名单），绝不存页面正文，不进同步、导出或备份快照。
- **自建确认浮层**：退出本机账户、清空日志、恢复上一份快照、导入 JSON 失败提示改用自建 `#ob-modal` 确认/提示浮层（取消/确认/Escape/遮罩点击语义与既有确认气泡一致）；源码中 `window.confirm(` 从 7 处降到 4 处（仅保留 AI 提示词管理 3 处与 AI API Key 清除确认 1 处），`alert(` 清零。AI API Key 输入保留原生 `window.prompt`：原生输入不把内容暴露给页面 DOM/事件，是本脚本刻意的秘密输入路径（源码注释已说明）。
- **文案同步**：面板内「规则」分组与关键词管理入口的指引文案改为指向现行 UI；被关键词规则自动写入的身份不出现在「最近本地屏蔽操作」（规则会再次写入，撤销会误导），需在弹幕管理器「恢复并例外」处理——该边界已写入面板文案。

## 不变边界

- 主名单存储格式（`omniblock:data:v1` schema）、同步协议、平台适配器与屏蔽执行链不变；`undoToastSeconds` 作为普通设置随既有设置快照同步。
- recent-actions 独立 GM 键与 AI 用量计数同级，不进入 `snapshotObject` 的 persons/settings 序列化（有源码级断言）。
- AI 默认关闭、人工确认门槛、平台写入红线、身份规范化前提全部不变；EventLog 事件与脱敏规则不变。
- 深色模式在 OB-UI-003，本版本不涉及。

## 已知限制与下一步

- 「最近本地屏蔽操作」的撤销只移除本地名单身份；对弹幕 hash-only 记录，移除后同文案弹幕会重新出现（与既有撤销语义一致）。撤销不会恢复关键词规则例外状态。
- 后台 UID 增强（B站 AI 弹幕确认后的补充身份）有自己的 toast 撤销，不重复计入最近操作列表；其撤销后最近操作条目仍显示原基础身份数。
- 名单搜索目前匹配备注/身份键原文与昵称标签，不做拼音或模糊匹配；空态文案已引导调整筛选。
