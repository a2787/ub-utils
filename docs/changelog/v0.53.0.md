## 用户可见变化

- AI 提示词把“是否命中屏蔽规则”和“事实是否得到核查”拆成独立字段：`claimType`、`verificationStatus`、`verificationMethod`、`ruleMatched`。
- 没有引用、没有检索结果、模型暂时不知道、单句事实陈述或语境不足，不再单独构成“虚假/谣言”的屏蔽理由。旧响应即使返回 `decision=block`，只要理由落在“未经证实/无可核实依据”等保守边界，也会被客户端降为延后，不进入可勾选候选。
- 规则性攻击、广告等非事实性违规继续进入原有人工审核；有明确正面矛盾依据的事实性结果仍可进入人工审核，最终仍需用户确认才写入本地名单。
- AI 状态和审核弹窗会显示因事实/语境尚未核查而保留的数量，以及可执行候选的核查状态/依据。

## 设计边界

当前 userscript 只向用户配置的 loopback Chat Completions 网关发送截短正文；本候选没有增加公共搜索、浏览器外发或新的扩展权限，不把模型内部记忆冒充外部来源。真正的联网事实核查需要另立检索通道，明确来源可信度、隐私、缓存、失败回退和成本后再实现。

关键词优先级、人工审核、反馈账本、身份键、B站 hash→UID 按需关联、80 条批次和平台写入边界均保持不变。
