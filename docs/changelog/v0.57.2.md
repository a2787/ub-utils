# OmniBlock v0.57.2：自动弹幕正则安全边界

日期：2026-09-12
状态：已发布

## 用户可见变化

- 在 B站/抖音「内容屏蔽」弹窗的「关键词屏蔽」标签里保存正则规则时，明显可能引发灾难性回溯的高风险表达式会被拒绝保存，并给出可理解的原因。典型被拒形态：重复的分组内部还套着可变长度匹配（如 `(a+)+`），以及量词分组的多个分支以相同字符开头（如 `(a|aa)+`）。
- 合法正则不受影响：分支以固定字符/字符类封口（如 `(\w+\.)*example\.com`）、分支首字符互不重叠（如 `(cat|dog)+`）、固定次数重复等形态照常保存。
- 这是保守启发式，只拦截明显危险形态，拿不准的形态仍会放行；已保存的规则不会在升级或重新加载时被悄悄删除，仍按原样参与匹配。
- 热路径的规则匹配继续复用按平台缓存的已编译正则（v0.57.1 已有），本轮为该行为补了回归断言，不为每条弹幕重复构造 RegExp。

## 实现边界

- 风险判定是保守启发式，不是完备的正则分析：只拒绝上述两类"明显"形态；更隐蔽的回溯形态（如 `(\w+\w)*`）不会被拦截，后续如需更严判定须另立计划评估误伤面。
- 拒绝只发生在保存入口（设置页与内容弹窗共用 `DanmakuRules.add`）；导入兼容 v1 格式时不做追溯删除，避免悄悄改动用户既有规则。
- 每个规则世代（Store 变更到下次变更之间）每平台只编译一次；本轮新增 `DanmakuRules.status()` 诊断计数用于回归断言，不进入用户界面。

## 验证证据

- `structure regression`：`node test/danmaku-auto.cjs` 8/8；新增 AUTO-REGEX-SAFETY 用例在旧行为上失败后转通过：`(a+)+$`、`(a|aa)+` 保存被拒且原因含"回溯"，`(\w+\.)*example\.com`、`(cat|dog)+` 正常保存，直接写入的已存风险规则仍参与匹配，一个规则世代内 51 次匹配只编译一次。
- `structure regression`：B站 quickblock 38/38、跨平台适配器 28/28、通用回归 20/20；维护总检本地项通过。
- `real-site verified`：2026-09-11 匿名隔离只读会话（B站/微博）与本轮专用 Chrome 登录态只读探针分别确认脚本在真实页面正常加载；本项改动不触及页面入口结构，登录态探针结果见 [当前维护状态](../maintenance/CURRENT.md)。
- 本轮维护总检中的抖音匿名隔离探针仍停在验证码中间页，维持 `blocked`。

## 安装与回滚

- `@updateURL`/`@downloadURL` 指向 raw master；发布后 Tampermonkey 在下次检查更新时自动升级到 `0.57.2`，也可在管理面板手动"检查更新"。
- 回滚时保留用户现有 Tampermonkey 数据（含已保存规则），只恢复 v0.57.1；本版本没有修改存储格式、同步服务或账户数据。
