# OmniBlock v0.57.0：Tampermonkey 移动端适配、API 直连与账户级加密同步

日期：2026-09-11
状态：本地候选，未公开发布

## 用户可见变化

- `omniblock.user.js` 继续是电脑与平板共同使用的交付物。设置面板、AI 审核浮层、内容管理器、标签和输入控件增加窄屏、安全区和触控适配；不要求平板安装独立 MV3 扩展。
- AI 只保留 `direct` 模式：用户填写 OpenAI-compatible API 地址和模型名，再通过“设置/更换本机 Key”保存设备本地 Key。Key 只出现在 `Authorization` 请求头，不进入页面对象、请求正文、导出文件或同步文档；不加入本地模型，也不把本机网关作为主链路。
- 设置页增加账户注册、登录、退出和显式“立即同步（合并）”。用户在不同设备使用同一账户和同步口令时，名单、可同步设置、AI 提示词个性化和反馈状态在客户端加密后合并。

## 实现边界

- userscript 使用 Tampermonkey 的 `GM_xmlhttpRequest` 直接访问配置的 HTTPS provider；首次访问未声明域名时由 Tampermonkey 展示 `@connect *` 的权限确认。provider 地址拒绝用户名、密码、查询串和片段；Key 不写入页面全局。
- `sync/sync-core.js` 与 userscript 内同步模块使用相同的 envelope、PBKDF2-SHA-256、AES-256-GCM、账户 AAD、设备级逻辑时钟、墓碑、确定性合并和 CAS 冲突重试协议。`sync-server/server.py` 只保存账户认证材料和 opaque 密文，不解密同步正文。
- 密码只在注册/登录按钮处理期间存在于内存；同步口令只在同步按钮处理期间存在于内存；访问令牌、设备标识和本地同步文档使用独立的 GM 存储。API Key、密码、同步口令、访问令牌、日志、备份和自动快照不进入同步文档。
- 同步默认不自动执行；网络短暂失败只进行有界重试。东京机已部署独立 `omniblock-sync` 服务和独立 SQLite 数据库，
  当前通过 Cloudflare Quick Tunnel 提供 HTTPS 入口；Quick Tunnel 重启后可能更换地址，固定域名/命名隧道不在本轮范围。
- `extension/`、`test/product-extension.cjs` 和旧网关目录保留为上一轮实验/历史兼容产物，不是 v0.57.0 的安装路径或 AI 主链路。

- `structure regression`：AI screening、AI bridge 兼容性、AI 多平台、内容 AI、内容覆盖、提示词系统/评测、批次、自动加载、watchdog、通用状态、平台适配器、同步核心和独立 Python 服务按维护矩阵验证；未执行平台写入。
- `real-site verified`：2026-09-11，东京独立同步服务本地 health 与 HTTPS Quick Tunnel `/healthz` 返回 `200`，服务标识为
  `omniblock-sync`；部署源码 SHA-256 与本地 `sync-server/server.py` 一致。

## 迁移与回滚

- 电脑端先保留现有 Tampermonkey 脚本和本地数据，安装本候选后逐个平台只读检查；平板端导入同一个 userscript。AI Key 需要在每台设备分别设置，不从云端恢复。
- 首次同步前在两台设备配置同一账户和同一同步口令，点击“立即同步（合并）”；同步失败时保留当前本地文档和错误状态，不删除本地名单。退出账户只清除本机令牌，不删除云端密文。
- 本地候选发布状态：userscript 已形成本地选择性 commit，未 push、未创建 tag/Release；独立同步服务已部署，未执行平台写入。
