# OmniBlock v0.57.3：AI 直连配置连通性测试与瞬态重试

日期：2026-09-12
状态：本地候选（发布需当轮授权）

## 用户可见变化

- AI 设置（关键词屏蔽弹窗的 AI 标签）新增 **「测试连接」** 按钮：填好 API 地址、模型名和本机 Key 后，点一下即发送一个 `max_tokens=1` 的最小请求验证 provider 是否可用，成功显示延迟毫秒数，失败显示可理解原因（地址非法 / 未设 Key / HTTP 401 / 限流等）。测试请求不进入分析管线、不写任何状态。
- 直连 AI 批量请求遇到瞬态失败（HTTP 429、5xx、请求超时、网络抖动）自动**重试一次**（1.5 秒退避），不再让整轮分析因单次抖动失败；取消、分析代次过期与 4xx 语义错误（如 Key 无效的 401）不重试，失败状态保持可理解。
- 适配任意 OpenAI-compatible provider（如官方 DeepSeek API）：请求体保持 `{model, temperature: 0, messages}` 标准形态，Key 只存在于 `Authorization` 头。

## 实现边界

- 「测试连接」复用与批量分析相同的 GM 跨源传输与错误文案，15 秒超时；先落盘当前输入框中的地址/模型再测试，避免输入框与已保存配置不一致造成误报。
- 重试只发生一次，重试计数进入分析耗时结构（`providerRetries`）；不改变 80 条分批、800 字符截短与人工审核门槛。
- 测试按钮与状态行沿用 AI 面板既有触控目标样式（44px）。

## 验证证据

- `structure regression`：`node test/ai-screening.cjs` 25 项全绿；新增 AI-24：provider 首次返回 429 后自动重试，分析靠第二次请求完成（旧行为整轮失败），后续增量分析不受影响。
- `structure regression`：`node test/userscript-product.cjs` 全绿；新增「测试连接」按钮用例——mock provider 下点击后状态行显示"连接成功"并带延迟。
- 直连请求体与 Key 隔离边界沿用 v0.57.2 既有断言（Key 只在 Authorization 头，不进请求正文/导出/同步状态）。

## 安装与回滚

- `@updateURL`/`@downloadURL` 指向 raw master；发布后 Tampermonkey 下次检查更新自动升级。
- 回滚仅恢复 v0.57.2，用户数据、规则与 Key 保留；本版本没有修改存储格式、同步服务或账户数据。
