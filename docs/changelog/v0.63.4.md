# OmniBlock v0.63.4

日期：2026-11-19 · `@version 0.63.4` · 构建：`0.63.4-discovery-fixes`
状态：已公开发布——tag `v0.63.4` 指向提交 `9ffbd0dfb3c82084b5f3613155f9885b9b1a7bda`，GitHub Release [v0.63.4](https://github.com/a2787/ub-utils/releases/tag/v0.63.4) 已创建，公开 raw 已核验返回 `@version 0.63.4` / 构建 `0.63.4-discovery-fixes`（源码含首次引导键 `omniblock:ui-hint:v1`）。证据为结构回归（`structure regression`，仅本地夹具验证），未做真实站点验证。功能提交 `607d04faf68c6077429081f0dec17f83968ef11e`，工作区 userscript SHA-256 `c05340aa7c74853b171a89861092b7d8426553cf8607473bbfe077738bed33be`。
关联：三项可发现性改进——桌面控制坞设置入口常驻可见、设置面板「规则」分组填实、首次访问一次性提示。

本条目记录 v0.63.3 之后的一轮用户可发现性改进：让收起态控制坞里的设置齿轮常驻可见（低对比度）、把此前点进去扑空的「规则」分组补上真正可用的管理入口、并给首次访问的用户一次性提示入口位置。三项同属"让已有功能能被用户找到"的改进，合并为 0.63.4 单一发布。只改 UI 呈现与入口，不改交互行为、触控端与存储数据层；未取得真实站点证据。

## 问题

- 入口不可见：桌面端控制坞（FloatingDock）收起态下，设置齿轮 `#ob-gear` 被 CSS `transform: translateX(32px)` 推出可视边缘，只露出一条边，实际上不可见。
- 无首次引导：产品内没有任何提示告诉新用户这个入口的存在，用户不读文档就无从得知如何打开设置。
- 2026-11-18 在 B站/微博/知乎/贴吧四平台桌面实测，截图全部看不到齿轮；最后只能靠 DOM 中 `aria-label="打开 OmniBlock 设置"` 才确认入口确实存在。该实测用于定位问题，不作为本轮修复后的验证证据。
- 「规则」分组空壳：设置面板「规则」分组原本只有两段指路文字、零控件，用户按导航点进去扑空，看不到可操作的规则管理入口。
- 新用户无引导：没有一次性提示说明 OmniBlock 已启用以及设置入口在哪，首次挂载后用户容易忽略右下角的齿轮。

## 修复

1. 控制坞收起态齿轮常驻可见：`#ob-gear` 收起态样式改为 `transform: translateX(0); opacity: .55`——齿轮常驻可见，但刻意保持低对比度，避免在非悬停状态抢夺注意力；悬停或键盘聚焦后由既有 expanded 规则把 opacity 恢复到 1，正常交互体验不变。其余行为完全不变：其他工具按钮仍为悬停展开、1800ms 自动收起保留、触控端（本就常驻展开）未改。
2. 设置面板「规则」分组填实：在「规则」分组加入 B站/抖音规则管理两个按钮（id `#ob-rules-bili` / `#ob-rules-douyin`），复用 `openKeywordManager`；分组 1 的原按钮保留（`test/rule-manager.cjs:171-172` 依赖 `#ob-open-rules-*` 选择器）。该函数用硬编码 adapter、不读当前平台，实测在微博页点击也能打开对应平台的管理界面。
3. 首次访问一次性提示：新用户首次在某站点挂载后，齿轮左侧显示两行浮条「OmniBlock 已启用 / 本地内容屏蔽工具，点右下角 ⚙ 设置」，可点 × 关闭。标志位存独立键 `omniblock:ui-hint:v1`，直走 `GM_getValue`/`GM_setValue`，不经过 Store/persist/键白名单（避免在 v0.63.3 数据层闸门最敏感路径上增加高频写）；读失败按"没提示过"处理；降级态可显示但零写入（与 HEAD 基线对照 `writesByKey` 证实）；点齿轮也算已知入口。

## 边界与限制

- 已随 tag `v0.63.4` 与 GitHub Release 公开发布，公开安装地址已提供本修复；本次发布未做真实站点验证，公开证据仅为结构回归。
- 未做真实站点验证：三项改动均只在本地夹具中通过用例、computed style 与选择器确认，真实浏览器/DOM 环境下的最终呈现尚未复核。
- UI 呈现与入口之外不改行为：控制坞自动收起、其他按钮悬停展开、触控端行为均未改动；规则按钮复用 `openKeywordManager`，未新增规则解析逻辑。
- 一次性提示绕开数据层：`omniblock:ui-hint:v1` 独立键直走 `GM_getValue`/`GM_setValue`，不进 Store/persist/键白名单；降级态零写入，读失败按未提示处理——牺牲跨设备的提示状态一致性，换取不在 v0.63.3 数据层闸门的高频写路径上引入风险。
