# OmniBlock v0.63.4

日期：2026-11-19 · `@version 0.63.4` · 构建：`0.63.4-dock-visible`
状态：本地候选，未公开发布；未 push、未打 tag、未建 Release；当前公开版本仍为 v0.63.3。证据为结构回归（`structure regression`，仅本地夹具验证），未做真实站点验证。源码已提交 `695366b21fb6b64929d8bf6dfd2bf6a0d4ac5cc1`（当前 HEAD），工作区 userscript SHA-256 `1db150709d7924e4cfd84cf8ef9fc8d99ec6c9145b794ef5b4c30c5c22d63c21`。
关联：桌面端控制坞（FloatingDock）收起态设置入口可见性修复

本条目记录 v0.63.3 之后的一轮用户可见入口修复：让收起态控制坞里的设置齿轮常驻可见（低对比度），
解决"入口存在但看不见、也无首次引导"的问题。本轮只改 CSS 呈现，不改交互行为与触控端；
未取得真实站点证据，也不构成公开发布。

## 问题

- 桌面端控制坞（FloatingDock）收起态下，设置齿轮 `#ob-gear` 被 CSS `transform: translateX(32px)`
  推出可视边缘，只露出一条边，实际上不可见。
- 产品内没有任何首次引导提示该入口的存在，用户不读文档就无从得知如何打开设置。
- 2026-11-18 在 B站/微博/知乎/贴吧四平台桌面实测，截图全部看不到齿轮；最后只能靠 DOM 中
  `aria-label="打开 OmniBlock 设置"` 才确认入口确实存在。该实测用于定位问题，不作为本轮修复后的验证证据。

## 修复

- 将 `#ob-gear` 收起态样式改为 `transform: translateX(0); opacity: .55`：齿轮常驻可见，
  但刻意保持低对比度，避免在非悬停状态抢夺注意力。
- 悬停或键盘聚焦后，由既有 expanded 规则把 opacity 恢复到 1，正常交互体验不变。
- 其余行为完全不变：其他工具按钮仍为悬停展开、1800ms 自动收起保留、触控端（本就常驻展开）未改。

## 回归证据

`structure regression`（仅本地夹具验证，未做真实站点验证，因此不记 `real-site verified`）：

- `test/run.cjs`：20/20（E4 控制坞用例通过）。
- `test/state.cjs`：9/9。
- `test/userscript-product.cjs`：7/7。
- computed style 实测：收起态 opacity 0.55 / 展开态 1 / 触控态 1，符合"常驻可见但低对比度"的设计。

四平台实测（2026-11-18）仅用于暴露问题，发生在修复之前；本轮修复未在任何真实站点复验。

## 边界与限制

- 本轮为本地候选，未 push、未打 tag、未建 Release；当前公开版本仍为 v0.63.3，公开安装地址未提供本修复。
- 未做真实站点验证：入口可见性只在本地夹具中通过 computed style 与用例确认，真实浏览器/DOM
  环境下的最终呈现尚未复核。
- 只改 `#ob-gear` 收起态的 CSS 呈现；控制坞自动收起、其他按钮悬停展开与触控端行为均未改动。
