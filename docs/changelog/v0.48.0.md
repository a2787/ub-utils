# OmniBlock v0.48.0

候选日期：2026-09-07

## 用户可见变化

- B站已有的 AI 评论/弹幕采集、预设规则、页面附加规则、多选审核和无身份候选只读边界继续保留。
- 抖音当前页面新增同一套 AI 采集入口：当前已观察到的评论和弹幕可以一起进入分析；评论使用已有 `douyin:secuid`，
  弹幕保留当前 DOM 已确认的 `douyin:uid`/`douyin:secuid`。身份无法确认的弹幕仍只显示正文，不提供可执行屏蔽。
- 抖音 AI 不自动展开评论、不自动滚动页面、不调用私有接口，只消费用户已经看到且当前会话缓存下来的内容。精选/推荐流同一路由换片时，
  播放器身份变化会清空旧弹幕正文和 AI 会话，普通弹幕属性变化不会触发重复模型请求。
- 网关日常启动新增根目录 [`启动网关.cmd`](../../启动网关.cmd)。它只调用 PowerShell 7 的 `gateway\start.ps1`，保留启动/健康检查错误窗口，
  不包含 API Key，不安装系统服务、不修改注册表。设置页同步说明该入口；设置页本身不直接启动宿主机进程。
- 修复 AI 分析在浏览器 GM/XHR 桥接不回调时永久停留在加载态的问题：客户端增加独立 watchdog，超时会进入失败状态。
- 修复本地 LiteLLM 的 18 秒请求 + 1 次重试与客户端约 20 秒预算错位的问题：userscript 与持久化开发扩展 service worker 统一使用 60 秒上限，仍保留无回调 watchdog 失败。
- 修复持久化开发扩展桥接处于 `degraded/ready-timeout` 时仍等待完整 watchdog 的问题：现在会快速报告桥接不可用，并在 loopback 地址有效但本地请求失败时明确提示检查网关/浏览器桥接，不再追加误导性的地址限制文案。
- 修复当前页内容超过 80 条时只分析前 80 条的问题：当前已经观察到的记录会按每批最多 80 条、每批总文本预算顺序请求，
  各批结果合并后再进入一个人工审核框；加载态显示总数和批次进度。
- 修复抖音评论/弹幕正文末尾混入“喜欢”“举报”“回复”“分享”“展开 N 条回复”等自带控件文字的问题；只清理可确认的尾部控件词，正文自身出现同名词时保留。
- 修复抖音真实探针复用用户标签页时遗留 document-start 测试 shim 的问题。探针现在保存并移除 CDP 注入脚本标识，避免 no-op 测试桥接覆盖真实 GM 请求。
- 持久 MV3 开发扩展的窄 AI POST 改由 service worker 发起，并在 worker 边界再次校验 loopback/JSON 白名单，避免 HTTPS 平台页直接跨源请求本机 HTTP 网关被浏览器网络边界卡住。

## 实现与安全边界

- AI 仍默认关闭，模型输出仍必须进入人工审核；只有用户确认且候选带已有规范身份时，才复用现有名单写入链路。
- B站和抖音发往网关的 payload 只包含规则、`kind`、临时项目编号和截短正文，不发送 UID、sec_uid、弹幕 hash、Cookie、完整 URL、
  本地名单或 provider API Key。
- 抖音 AI 正文独立限制为当前视频会话最多 1200 条，正文不保留 DOM 引用；已有弹幕管理器继续使用自己的发送者/节点上限。
- 同 URL 换片通过既有活动播放器身份观察器转发到共享页面信号，AI 只在会话身份变化时取消旧请求、清审核框并有界重试；没有新增全页
  MutationObserver 或高频轮询。
