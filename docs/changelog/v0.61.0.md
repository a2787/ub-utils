# OmniBlock v0.61.0 - AI 已分析持久缓存、自动批量上限与只看评论

日期：2026-10-27。计划项：OB-AI-016（见 [PLAN](../maintenance/PLAN.md)）。状态：已随 2026-10-28 统一公开发布（tag/Release/raw 已核验）；候选构建 `0.61.0-ai-analysis-cache`。

## 背景

v0.58.0 让自动分析只挂在独立开关上，但已分析记录集合 `autoAnalyzedRecordIds` 仍只存活于当前页面会话：重访同一页面会把相同内容再次发给 provider 重新计费；长评论区一次自动分析可能串行发出大量批次，没有单页上限；自动模式也不区分评论与弹幕。本版本（OB-AI-016）收敛这批 AI 成本问题。

## 用户可见变化

- **已分析记录持久缓存**：自动模式成功分析过的记录进入本机缓存（独立 GM 键 `omniblock:ai-analyzed:v1`），TTL 7 天、LRU 上限 2000 条、延迟 2 秒合并落盘，页面隐藏（PageLifecycle hidden）与运行时销毁时立即冲刷。重访同一页面时，已分析过的记录不再产生 provider 请求，状态保持 ready 且不重复计费。缓存整体带 generation（规则文本 + 提示词签名 + provider 地址 + 模型的哈希）：规则、提示词 profile、provider 或模型任一变化，下一次启动/设置变化时整体失效并重新分析。
- **缓存内容与边界**：条目只有稳定记录 ID（内容签名的 `ai-item-` 哈希）和最后分析时间戳——没有正文、昵称、身份键或 URL；不进入 Store 快照、账户同步、名单/提示词导出或备份。
- **手动分析完全不碰缓存**：「分析本页」既不查询也不写入缓存，点击即对当前页已观察内容完整重新分析；手动路径行为与 v0.60.0 逐字节一致（无上限、无跳过）。
- **自动批量上限**：自动模式每页最多发送 3 批（`AI_AUTO_MAX_BATCHES`，每批仍为 80 条/48,000 字符）；超出部分保持未分析、不做任何已分析记账。状态栏追加「已达本页自动分析批量上限（每页最多 3 批），其余 N 条可用「分析本页」手动处理。」；`ai.analysis.finish` 日志新增 `batchesSent` 与 `autoCappedRemaining`。手动分析不受上限约束。
- **自动分析只看评论（可选）**：AI 面板新增「自动分析只看评论（弹幕仅手动分析）」复选框（`aiAutoCommentsOnly`，默认关闭，须先启用 AI）。开启后自动分析跳过全部弹幕——不发送、不记账，之后仍可手动分析；评论与作品内容照常。手动分析不受影响。
- **状态计数更诚实**：当本轮因上限或只看评论没有覆盖全部已观察内容时，状态栏把「已分析当前页全部 N 条」改为「已分析当前页 X/N 条」。

## 不变边界

- AI 请求协议、批量常量（80 条/48,000 字符）、脱敏规则、人工审核与确认流程、事实核查门禁、`aiEnabled`/`aiAutoAnalyze` 开关语义全部不变；本版本不新增任何上传，缓存只在本机 GM 存储。
- 会话内增量分析语义不变：一次运行期间新到的评论/弹幕仍合并为收尾后的下一次有界增量运行；同页内容变化产生新记录签名，不受持久缓存影响。
- 平台适配、身份键规范与平台写入红线不变。

## 已知限制与下一步

- 缓存 LRU/TTL 只在加载与保存时清理；手动分析永远重新发送，因此「重访不计费」只承诺自动模式。
- 弹幕会话内容跨重访通常相同（同视频弹幕集合稳定），开启自动模式且未开「只看评论」时，弹幕也会被缓存跳过；这正是设计目标，但意味着新弹幕到达依赖既有内容信号触发增量。
- 后续项：OB-RULE-004（样本库）、OB-UI-003（深色模式）、OB-MAINT-003（dev-extension 用例与扫描噪声）。
