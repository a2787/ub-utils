# OmniBlock v0.59.0 - 关键词/正则规则管理升级

日期：2026-10-27。计划项：OB-RULE-003（见 [PLAN](../maintenance/PLAN.md)）。状态：本地候选，未 push、未 tag、未 Release。

## 背景

v0.58.0 及之前，关键词/正则规则只支持"添加 / 启停 / 删除"：改一条规则必须删除重建，没有备注、没有每条规则的
命中统计，同一条规则要在 B站和抖音各加一次，规则数据只能随整份快照导入导出，设置面板还残留旧自动规则区块的
死代码和"请在设置中停用规则"之类指向失效的文案。本版本把规则管理补齐为可持续运营的形态（OB-RULE-003）。

## 用户可见变化

- **就地编辑**：规则行的「编辑」按钮进入行内编辑——类型（关键词/正则）、内容、备注、作用域一次改完，保存后
  匹配即时生效，不再删除重建。规则 id 由内容派生，编辑后自动迁移该规则的命中计数。
- **每条规则备注**（≤200 字符，仅本机）：列表行以 📙 标记显示，悬停查看。
- **跨平台作用域**：编辑时可选「两个平台通用」，该规则同时参与 B站和抖音的关键词匹配；默认「仅本平台」。
  旧规则数据没有作用域字段，自动按原平台继续生效，行为不变。
- **每条规则命中计数**：本机持久累计（独立 GM 键 `omniblock:rule-hits:v1`，延迟落盘，不触发 Store 级联），
  规则行显示「命中 N」徽标，状态行显示平台累计；提供「命中清零」；删除规则时一并清理；编辑内容时计数迁移到
  新 id。计数只在本机，不进同步、导出或日志。
- **规则包导入/导出**：关键词面板新增「导出规则」「导入规则」（`omniblock.danmaku-rules` JSON，两平台规则
  一起打包）；导入经规范化、去重、单平台上限与正则安全校验（复用保存时的危险正则拒绝），结果给出新增/跳过
  重复/无效/危险正则的可解释计数。
- **设置面板规则管理入口**：「平台专用屏蔽入口」节新增「B站规则管理」「抖音规则管理」按钮——任意页面（包括
  非统一内容弹窗平台）都能打开同一个规则管理浮层，不再必须到对应平台页面。
- **清理**：删除设置面板已失去挂载点的旧自动规则代码（`autoStatusText`/`refreshAutoRules`/添加处理器）；
  修正弹幕管理器中"请在设置中停用或删除规则""可在设置中恢复规则作用"等指向失效的文案，改为指向「关键词屏蔽」
  标签。

## 不变边界

- 关键词/正则匹配仍是零 token 本地行为；命中→可靠身份写入本地名单、例外跳过的语义不变。
- 规则仍仅覆盖 B站/抖音；其他平台需先真站捕获结构（保持 OB-RULE-003 non-goals）。
- 规则引擎不决定平台身份、不执行存储写入的分层不变；PAKKU 等弹幕去重独立不受影响。

## 已知限制与下一步

- 命中计数是"匹配事件次数"（同一条弹幕重复匹配会重复计数），不是去重后的条数；状态行文案已注明本机累计。
- 相同 kind+pattern 的规则在两个平台各存一条时共享同一 id，命中计数按 `平台:id` 分开统计。
- 已屏蔽内容样本库与 AI 归纳提炼规则（用户设想）在 OB-RULE-004；设置面板信息架构在 OB-UI-001。
