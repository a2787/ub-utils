# OmniBlock 拉黑不上限（6 平台统一本地黑名单）

一个浏览器用户脚本：**一份本地黑名单，在 6 个平台已适配的内容条目中隐藏指定用户**。
无数量上限，名单与浏览数据只保存在本机、不会上传；脚本还会在独立的本机存储键里自动保留
最近 5 份名单快照（可关闭、可恢复上一份）。主动点击“检查更新”时会请求
GitHub；在 B站弹幕工具里主动点击 `UID?` 时，会匿名请求 B站用户卡片接口校验数字候选。
Tampermonkey 自身的例行更新请求取决于它的更新设置。

支持平台：**B站 · 微博 · 知乎 · 百度贴吧 · X(Twitter) · 抖音**（不含小红书）。

处理范围：
- 只有能从条目自身可靠解析出规范身份时，脚本才会隐藏内容或提供可执行的拉黑入口；
  解析不到就保持原样。评论、帖子/动态、搜索结果和作品列表的实际覆盖，以文末验证表为准。
- **B站视频弹幕**（从拦截或主动只读获取的数据段 `seg.so` 建立当前视频发送者列表，
  相同文案按组显示，单击或勾选批量会屏蔽组内全部发送者，并按 `mid_hash` 过滤；
  已屏蔽的评论 UID 会经 CRC32 正向映射到弹幕；也可主动查询 1–10 位 UID 候选并在人工
  核对后关联评论身份；唯一候选经用户卡片正向校验后直接关联，无需人工确认）
- **抖音视频弹幕**（网页弹幕带 `data-danmaku-user-id` 时按 uid 隐藏；悬停弹幕会浮出
  在弹幕文字左侧略有重叠、并随弹幕移动的「🚫 拉黑」按钮；右下角与齿轮同列的管理器会按当前视频本轮
  已观察到的可靠发送者去重，支持搜索、全选和批量屏蔽；精选/推荐流切换视频时会按当前播放器的视频标识
  清空上一条视频的观察缓存，避免旧弹幕带入新视频；打开管理器后可按需扫描视频时间轴以尽量触发懒加载，
  扫描结束会恢复原播放位置和播放状态；视频作者自己的弹幕会按当前作者 sec_uid 一并隐藏）
- **抖音评论**（评论右侧“三个点”打开的 portal/tooltip「举报评论」菜单旁会增加「🚫 本地拉黑」；右下角
  与齿轮同列的评论管理按钮会自动展开页面上带明确回复语义的子评论，并可搜索、按需滚动尽量加载，
  再勾选并批量屏蔽作者）
- **抖音推荐流**：刷到被屏蔽作者 → 视觉遮罩 + 自动切下一条（唯一一处"模拟操作"，带安全阀）

隐藏方式：已识别的评论和弹幕始终无提示、零占位消失；帖子、动态、搜索卡等其他内容
可在设置里选择折叠成灰条（默认，可追溯）或完全消失。

## 安装（傻瓜版）

1. 给浏览器装一个 **Tampermonkey**（油猴）插件：
   - Chrome / Edge：扩展商店搜 "Tampermonkey" 安装
   - 装好一次之后基本可以忘掉它
2. 把本项目的 `omniblock.user.js` 拖进 Tampermonkey：
   - 打开 Tampermonkey 管理面板 → 「实用工具」→「导入」→ 选 `omniblock.user.js`
   - 或把文件内容复制，新建脚本粘贴保存
3. 进任意支持的平台，右上角 Tampermonkey 图标 → 「OmniBlock 设置」即可管理名单、导出备份。

> v0.14.0 新增了 `api.bilibili.com` 连接权限，只在你主动查询弹幕 UID 候选时使用；请求
> 设置为匿名，不携带浏览器登录 Cookie，也不会发送本地黑名单或原始浏览数据。

> 改一行刷新页面即生效，调试最直观。也可发布到 GreasyFork 分享给别人。

## 更新方法（以后加功能 / 修 bug 怎么换新版）

你拖进 Tampermonkey 的是一份**本地副本**，原稿改了它不会自己变。新版获取有三条路：

**① 一键检查更新（最省事，日常推荐）**
- 打开设置面板（右下角 ⚙）→ 点「检查更新」。
- 它自动去仓库拉最新脚本、比对版本号：
  - 有新版 → 弹出 Tampermonkey 的「更新」页，**点一次「更新」即装好**（用户脚本无法在运行时自替换，这一下点击不可避免）；
  - 没新版 → 提示「已是最新」。
- Tampermonkey 菜单里也多了一条「检查更新」，面板关着也能用。

**② 全自动（彻底免拖文件，建议设置一次）**
- 在 Tampermonkey 里把本脚本「更新 → 模式」设为「自动」。
- 之后 TM 每天例行检查时**静默应用**新版，你完全不用管，也不用手动点。
- 平时让它自己跑；想立刻看结果时用 ① 点一下。

**③ 手动覆盖（兜底）**
- 把新文件再拖一次进 Tampermonkey，版本号更高会弹「更新吗」，点更新即可；或编辑粘贴保存。
- 黑名单名单、设置都还在，不会丢。

> 维护者开发阶段不会因为每次尝试都提高版本号：日常候选先通过专用调试浏览器和隔离夹具；进入明确的发布候选阶段时
> 才提高 `@version`，并继续保留“本地候选”状态。只有验证边界写清且取得本轮公开发布授权后才 push/tag/Release；
> Tampermonkey 只有在远端正式发布后才会把它识别为可更新版本。
> 仓库为公开 `https://github.com/a2787/ub-utils`，脚本头 `@updateURL`/`@downloadURL` 指向 GitHub raw 直连（jsDelivr 暂不可用，后续可切回以获国内加速）。仓库名/脚本名刻意低调（不含"拉黑/黑名单"显眼词），Pynseq 出处署名仍保留。

### 修复验收时如何确认当前页面确实用了新代码

从 v0.30.0 起，设置面板顶部和右下角齿轮都会显示「运行版本」与「构建」；齿轮还带有
`data-ob-version`、`data-ob-build`、`data-ob-runtime` 三个机器可读属性。维护修复时需要让
当前浏览器页面报告的版本和构建都与本轮源码一致，再观察平台行为；只看到 Tampermonkey 的
「已是最新」不代表工作区里尚未发布的修改已经安装。

用户脚本不能在运行时替换自身，所以「检查更新」发现候选版本后仍会打开 Tampermonkey 的安装页，
需要在该页点一次「更新/安装」，然后刷新原平台页面。若页面齿轮的构建标识没有变化，先不要继续
判断修复结果，把当前页面留在原处即可。

### 专用调试浏览器的持久运行方式（维护者）

开发验收不再把当前页面源码临时注入当作“安装成功”。实际用户运行仍由 Tampermonkey 负责；维护者的
专用调试浏览器则使用由当前源码生成的本地 MV3 开发扩展。扩展在每个匹配的新文档的 `document-start`
自动加载 userscript，并通过本地 `chrome.storage` 桥接 GM 存储，因此新建页面、刷新页面和切换平台都能
使用同一份本地状态。

一次性准备固定专用 Chrome profile：

```powershell
node test/dev-browser.cjs guide
node test/dev-browser.cjs ensure
```

首次在这个专用窗口打开 `chrome://extensions`，开启“开发者模式”，选择“加载已解压的扩展程序”，
载入命令输出中的 `test/_dev-extension` 目录。Chrome 会把这次加载保存到该专用 profile；以后新开支持
平台页面就会自动运行本地开发源码，不需要再对单页调用注入。源码修改后运行 `node test/dev-browser.cjs build`，
再在扩展页点击该开发扩展的刷新按钮即可。

当前 Google Chrome 版本会忽略自动化命令行的 `--disable-extensions-except`/`--load-extension` 组合，
所以启动器不再把这两个参数当成成功条件，也不会伪造“已加载”。如果需要确认当前安装是否真的作用于新页面，
在取得本轮登录态只读验证授权后，显式提供一个脱敏前的实际页面地址运行：

```powershell
node test/installed-browser-probe.cjs --url=https://www.bilibili.com/...
```

开发桥只允许 OmniBlock 自己的名单/备份/日志键和两类只读网络目标；主世界与隔离世界消息带构建期随机签名和单调序列，
页面拿不到 `window.GM_*` 能力。桥接不可用时会在 8 次尝试后有界降级，不会无限轮询。

该探针会在固定 CDP 会话中打开两个新页面，只读取脚本自己的运行版本、构建标识、齿轮和控制坞状态，
不会注入源码、读取 Cookie 或点击 B 站/抖音/微博的举报、拉黑、关注等平台写入控件。`node test/dev-extension.cjs`
则使用隔离临时 profile 和兼容 Chromium 浏览器打开人工合成页面做 `structure regression`；它证明自动加载
和存储桥接，不替代真实站点验收。旧的直接注入方式仅保留给隔离夹具和公开只读探针，不能作为专用浏览器安装证据。

### v0.46.0 - 受控生命周期、签名开发桥与分帧性能预算 - 2026-08-30

当前公开构建标识为 `0.46.0-signed-session-index-conflict-tieba-vue`；已创建
[v0.46.0 GitHub Release](https://github.com/a2787/ub-utils/releases/tag/v0.46.0)，当前公开版本为 0.46.0。

- 移除跨平台通用的评论悬浮 `🚫 拉黑` 浮层。微博评论继续使用已单独适配的「本地拉黑」和「屏蔽该楼回复」，
  其他平台也继续使用各自的评论、作者、作品、菜单、弹幕和批量入口；设置页保留的悬浮开关只控制平台专用入口，
  当前包括抖音弹幕跟随式本地拉黑，不再创建一个跨平台评论按钮。
- 高频平台新增 DOM 不再在 MutationObserver 回调内同步深扫。新增子树进入下一帧队列，每帧最多处理 32 个根，并以
  8ms 为时间预算；复杂树会续到下一帧，浅弹幕节点则能在一帧内批量处理。
- 页面资源由统一注册表持有。隐藏或 freeze 时暂停非必要工作，resume 后补一次同步；BFCache 暂存可恢复，普通 pagehide
  会幂等停止扫描器、观察器、订阅、timer 和 rAF。SPA 路由只由主扫描器统一检测并广播，不再让每个入口各建轮询。
- B站作者、微博作者、快速菜单、作品入口和评论批量入口改为活动信号触发的一次性防抖任务；没有相关 DOM 活动时不再
  周期唤醒。抖音/B站播放器确有必要的低频正确性兜底仍保留，并受页面可见性门控。
- 设置页“备份”区域会显示主名单人物数、身份数和序列化体积；接近专用开发扩展单值边界时分级提示导出/清理，
  不自动删除名单，也不新增人数硬上限。
- 详细日志继续保留用户动作和错误，被动事件继续聚合；分片大小使用缓存，不再在每次 flush 时重复序列化全部保留日期。
  可选诊断现在能分别看到 Mutation、扫描、微博布局、名单持久化和日志写入的次数、体积及最大耗时。
- 屏蔽始终走同一条运行路径：基本屏蔽和必要事件记录持续工作，详细诊断明细仍由设置页现有日志开关控制；不新增“第一资源模式”/“低资源模式”或独立“诊断模式”。
  若主名单写入失败，当前页会保留内存状态但返回失败并在设置页提示“未确认落盘”，不会伪造成功快照或 provider 通知。
- 名单身份查找使用惰性 key→人物索引，批量导入/作品级批量屏蔽不再为每组重复遍历全部人物；跨标签页变化在本页存在未确认落盘时会显示冲突并保留当前内存状态，避免静默覆盖。
- 评论管理器和楼中楼读取带页面/管理器会话代号与可取消边界；关闭面板、切换 SPA 路由或节点被回收后，旧结果只会安全丢弃，不会重新渲染或提交名单。
- 贴吧新版详情评论在捕获到 `.pb-comment-item` 且 Vue `userInfo.id` 为数字时可识别并屏蔽；首页 `.thread-card` 的不透明作者参数和未加载楼中楼不被猜测。
- 微博详情页虚拟评论在快速滚动触发物理行重排时，按空间位置而非暂时的 DOM 顺序累计多条隐藏行的补位，减少滚轮中的短暂重叠/空白；用户主页嵌套评论和其他平台路径不变。
- 原生菜单快捷入口在点击时优先重新读取仍连接的当前评论节点，只有 portal 与评论行断开时才使用最近快照；虚拟列表复用菜单不会把旧用户身份带到新用户，延迟打开的贴吧/知乎 portal 仍可安全完成识别。
- 持久开发扩展不再把 GM 能力挂到页面全局；桥接消息使用 HMAC-SHA256、来源和序列校验，存储键、只读 URL、请求方法、
  响应大小和超时都有白名单/上限。缺少隔离桥时约 4 秒内降级启动。

维护层新增唯一活动计划、架构边界、ADR 和机器门禁。完整版本说明、验证标签和当前限制见
[v0.46.0 版本条目](docs/changelog/v0.46.0.md) 与 [当前维护状态](docs/maintenance/CURRENT.md)。

### 上一发布版本 v0.45.0 - 全插件性能与资源效率优化 - 2026-08-29

该发布版本的构建标识为 `0.45.0-persistent-runtime-floating-dock-log-aggregation-performance-resource-bounds`。
本版本在上一轮平台分列、作品级屏蔽和详细日志的基础上，继续包含以下升级：

- 设置页的屏蔽名单改为按平台分列；每一列有自己的滚动区域，不会因为另一平台名单很长而把所有平台混在同一条长列表里。
- 抖音视频、微博帖子和 B 站动态详情页（包括动态视频）会在能可靠确认作品作者时显示「🚫 屏蔽作品」。确认后，
  适配器只在该作品的作用域内收集作者、主评论、子评论和可确认的弹幕发送者，去重后一次写入本地名单；已经屏蔽的身份不会重复写入，
  取消提示中的撤销只移除本次新增身份。读取范围不可靠或没有可靠身份时会明确显示「部分」/「无可靠身份」，不会猜测用户，也不会触发平台官方拉黑。
  抖音和微博按当前作品内可展开的控件、DOM 和安全滚动读取；B 站动态作者来自页面状态，评论/子评论按当前 DOM，动态视频弹幕只纳入本次页面已观察到的弹幕会话，
  所以三平台都不能把该入口理解成平台接口意义上的绝对全量。
- 设置页新增「反馈与日志」。日志默认开启，按本地日期保存完整的 OmniBlock 事件流：生命周期、平台选择、存储写入、扫描批次、DOM 变化摘要、
  用户操作、评论/楼层/作品收集、分页和安全滚动进度、弹幕扫描、状态转移以及错误。用户操作、屏蔽/恢复、状态转移和错误逐条记录；
  空闲页面的高频 DOM 变化、扫描和逐项扫描改为 10 秒窗口汇总，保留批次数、节点/类型计数、扫描耗时、选择器统计和少量安全样本，避免日志自身制造持续写入。
  页面只渲染当天最近 800 条以避免设置页卡顿，「导出日志 JSON」包含保留范围内的全部事件；还可以复制诊断摘要、按开关暂停记录或清空日志。
  日志只保存在本机，默认保留最近 30 天、每天最多 50,000 条、总大小最多约 16 MB；不记录 Cookie、Token、请求头、身份键、正文、完整 URL、原始 HTML 或异常堆栈。
- 抖音视频页的弹幕收集会在同一轮扫描中复用活动播放器根节点和视频会话键；未启用抖音自动弹幕规则时，逐条弹幕直接走快速路径，
  不会为每条弹幕重新递归遍历整页 DOM。播放器切换后仍会在下一轮重新确认当前根节点，避免把旧视频的弹幕带入新视频。
- 通用页面扫描器使用共享 MutationObserver、增量脏节点和 Shadow DOM 单次遍历；后台标签页暂停观察器，恢复前台时再补一次同步。
  B站/抖音弹幕、作者入口、评论批量入口和作品入口均通过脏标记与低频门控更新，不在每个无关 DOM 变化上重复深扫。
- 高频运行缓存都有边界：评论管理器最多保留 20,000 条当前会话记录，B站/抖音/微博的观察、查询和进度索引也有上限；缓存只保留必要的身份/展示元数据，
  不延长已被虚拟列表回收的 DOM 节点生命周期。达到评论管理器上限时会明确显示“部分/已达到本地记录上限”，不会假装已取全。
- 右下角设置、B 站/抖音弹幕和评论入口统一进入一个控制坞：默认半隐藏齿轮和隐藏页面级悬浮入口；鼠标悬停齿轮或键盘聚焦时展开，
  入口使用淡入/滑入动效。鼠标从齿轮移向入口时会保留短暂交互窗口，打开设置或管理器后保持展开，关闭后自动收起；遵循系统“减少动态效果”偏好时关闭过渡动画。

#### 本轮结构审视结论

- 运行时仍是单个 userscript 文件，但存储、事件日志、通用扫描器、平台适配器和 UI 已通过闭包划分职责；本轮保留这个发布形态，
  避免把跨平台身份键和平台 DOM 适配拆分时引入未验证的打包/加载差异。
- 同一文档重复执行由运行锁拒绝，开发扩展在恢复 GM 存储快照后才启动扫描；页面级入口的创建/销毁由平台逻辑负责，显示、保持和收起由统一控制坞负责。
- 现有平台适配仍依赖动态 DOM、Shadow DOM、虚拟列表和平台版本；这些属于已记录的结构风险，继续用平台专属夹具和真实只读探针分别验证，
  不把一个平台的选择器或真站结果扩写到另一个平台。

## 怎么用

- **右键**任意评论/帖子 → 弹出自建菜单「🚫 拉黑此用户」→ 确认。（B站评论/动态在 Shadow DOM 内，已做穿透，同样可用）
- 鼠标**悬停**评论不会再生成跨平台通用按钮；各平台专用入口显示在对应评论或操作区，抖音弹幕仍可在弹幕节点附近显示专用跟随按钮。
- 页面右下角有常驻 **⚙ 按钮**，默认半隐藏在右边框只露出边缘；鼠标悬停或键盘聚焦后控制坞展开，点开就是设置面板（不再需要去 Tampermonkey 菜单里找）。
- 设置面板顶部会显示当前实际运行的版本和构建标识，便于确认刷新后不是旧脚本残留。
- 设置面板里有 **「检查更新」按钮**：点一下自动比对仓库版本，有新版会弹出 Tampermonkey「更新」页（点一次即装）。想彻底免拖文件，按「更新方法 ②」把 TM 更新模式设为「自动」即可。
- 设置面板里可手动按平台 + 身份值添加、删除、导出/导入 JSON 备份；默认自动保留最近 5 份
  本地快照，可关闭并恢复上一份。快照只用于误删、错误导入或主名单键损坏后的回退，浏览器
  配置整体丢失时仍应把 JSON 导出到下载目录或其他设备。0.46.0 版本还会显示主名单人数、身份数和
  序列化体积，并在接近本地存储边界时给出软提示，不会自动删名单。
- 设置面板名单按平台分列、每列独立滚动；自动记录了评论或弹幕依据的条目会显示备注，鼠标悬停名单行可
  看到「屏蔽依据」。当前版本还会在这里显示「反馈与日志」区域，可导出完整保留范围内的事件 JSON。
- 总开关、其他内容的隐藏方式和入口开关都即时生效：关闭屏蔽或删除名单后，当前页已折叠/隐藏的内容会立即恢复，不需要刷新。
- 当前版本在抖音视频、微博帖子和 B 站动态详情页提供「🚫 屏蔽作品」入口。它只处理当前作品作用域内可靠识别到的作者、主评论、子评论和弹幕发送者，
  先显示收集计数和「部分」警告，再由用户确认；一次操作有撤销入口，撤销只删除这次新增的身份。
- 命中黑名单的评论不会显示恢复条或“内容已屏蔽”文字，也不保留空行；下一条评论会直接补位。弹幕条目同样直接隐藏。
- B站视频页右下角始终显示 **「弹幕屏蔽(N)」**；数据尚未就绪时显示 `(0)`，脚本会主动
  读取当前视频首段，失败时面板内可点「重新读取」。打开后按弹幕文案分组并显示发送者数；
  点击一组会屏蔽该文案的全部未屏蔽发送者，已屏蔽的文案组仍保留在列表中并以灰色显示，
  可点「取消屏蔽」恢复；勾选多组时会展开并去重所有未屏蔽发送者。它不依赖移动
  弹幕的举报菜单，并兼容 PAKKU 接管播放器弹幕请求的加载顺序。右侧原生弹幕列表会按
  行的显示时间按需读取对应的 6 分钟数据段：唯一发送者显示「本地拉黑」，同文案多发送者
  显示「本地拉黑全部(N)」，尚未读取或暂未匹配时显示禁用的读取状态。每组旁边的 `UID?`
  会匿名查询可能发送者并请求用户卡片接口剔除不存在账号：唯一且已正向校验的候选直接
  显示「拉黑本人」，点击后同时保存 hash 与 UID，不再弹二次确认；同一文案存在多个存活
  候选（CRC32 碰撞）时仍显示「确认并拉黑」，打开主页核对后才会合并身份。
- B站弹幕管理器中，如果某组是自动规则命中的结果，「恢复并例外」会按当前可靠的 hash（以及已经确认的 UID）
  保存自动规则例外，同时取消当前本地屏蔽；这不会关闭关键词/正则规则，也不会影响其他发送者。文案对应多个发送者
  且无法逐一对应时，原生弹幕列表仍按安全边界处理，需以管理器中可靠身份为准。
- 自动弹幕规则的设置面板按平台分开管理：可分别为 B站和抖音添加关键词或正则表达式，
  勾选启用或删除规则。规则只在本机匹配弹幕文字；命中后自动走该平台已有的本地屏蔽链，不触发举报、官方拉黑
  或 PAKKU 去重。B站普通弹幕没有原始 UID 时会保留 `mid_hash`，唯一且经过公开用户卡片正向校验的候选才会
  与 UID 关联；抖音没有可靠身份的命中只隐藏当前节点，不会写入猜测身份。规则命中的发送者可在弹幕管理器中点
  「恢复并例外」：当前身份会恢复显示并加入对应平台的例外列表，其他命中仍继续屏蔽；设置里的「恢复规则」会删除
  例外并让规则重新作用于该身份。删除规则只停止后续自动匹配，已经写入本地名单的普通身份仍需在名单中手动删除。
  设置面板和齿轮上的运行版本/构建标识可用于确认当前页面确实运行了本版本。
- 也可以直接把鼠标移到播放器里正在飘的一条弹幕上，弹幕上方会浮出「🚫 拉黑该弹幕
  发送者」，按钮会跟随弹幕移动，点一下即可；仅在这条弹幕能唯一对应一个发送者时出现。
- 微博详情页和用户主页帖子内当前已加载的每条评论操作区都有 **「本地拉黑」**；屏蔽后只让该评论无占位
  消失，包括旧版/懒加载结构的楼中楼；点击「共 N 条回复」打开的弹窗中，根评论和每条
  回复也各自使用自己的入口；展开行本身没有作者身份，不会注入按钮。被隐藏行的包装层
  会同步压成零高度并一起收掉，不留空白；如果前端使用 `vue-recycle-scroller`，正常补位
  会移动虚拟行的直接内容层，而不反复改写平台控制回收的外层 `transform`，所以下面的
  评论能连续上移且不会触发回收器频闪。平台若把列表 spacer 恢复为自己的原始基线，脚本
  会接受该基线，不与平台争夺同一个 `style`；撤销时恢复内容层、列表和包装层状态。
  微博详情页快速滚动时，回收器可能暂时把物理行按不同顺序复用；脚本会在检测到这种
  重排时按行当前 `translateY` 的空间顺序累计隐藏高度，避免按 DOM 顺序补位造成短暂
  重叠或空白。该修复只作用于已确认的详情页虚拟列表；遇到超大或无效位置仍沿用原有
  安全修复路径。
  只有确认虚拟行自身只包含被隐藏评论时才会补位。
  微博暂时回收、带 `opacity:0` 的非活动行会保留平台自己的回收位置，等它重新变为活动行后再补位，
  不会被脚本锁在页面外；登录态首轮渲染的临时超大行高也不会被当成真实评论高度缓存。
  没有本地屏蔽行时不会对普通虚拟评论反复做整列表布局扫描；已有补位工作的虚拟行或结构变化只会在同一批次
  观察回调内立即协调，单独的 spacer 回写只记录基线，避免评论较多时页面被脚本拖慢或变成
  页面无响应。某些版本的微博回收器可能因此保留少量末尾可滚动余量，但评论中间的空洞会由
  内容层补位消除。
  详情页的顶层评论即使由虚拟行内容层直接包在 `wbpro-list > item1` 中，也会使用同一套内容层补位；用户主页
  帖子内部更深处的 `wbpro-list` 评论仍只折叠自身，不会接管外层帖子回收行。
  用户主页里点击帖子自带的页内评论展开入口后，评论可能嵌套在整条帖子的回收行内部；脚本
  会把这种嵌套评论按普通评论容器处理，不把整条帖子误当成评论虚拟行，因此不会为隐藏评论
  移动帖子本身或下方帖子。
  热门/推荐等无限流页面里的帖子卡片由微博回收器管理；帖子作者的「本地拉黑作者」入口会挂在
  独立页面门户中，按作者链接的视口位置定位，不插入 `article/header` 布局树，也不改写回收行高度
  或列表 spacer。通过作者入口本地拉黑整条帖子时，卡片会压成零高度，下一条帖子的内容会从原位置补上；
  卡片里展示的预览评论仍按普通嵌套评论处理，不会被误当成详情页顶层评论列表。
  左下角批量入口同时统计当前微博作者和已加载评论作者，点赞/转发等用户列表弹窗里
  也有「拉黑全部」。
- 抖音视频弹幕：把鼠标移到正在飘的一条弹幕上，弹幕文字左侧略有重叠的位置会浮出「🚫 拉黑」
  按钮并跟随弹幕移动，点击后确认即本地拉黑该发送者，这条弹幕和之后同一发送者的弹幕都会消失；
  视频作者自己的弹幕在作者被屏蔽时也会一起消失。
- 抖音视频页右下角与齿轮同列有两个入口（从下到上依次为设置、弹幕、评论）：**「🚫 抖音弹幕屏蔽(N)」**
  打开多选弹窗，列出当前视频已经在页面上观察到且带可靠 `data-danmaku-user-id` 的发送者。相同发送者
  的多条弹幕只占一行，可搜索、全选并批量本地屏蔽；「尽量加载弹幕」会暂停并逐点扫描播放器时间轴，
  结束后恢复原播放位置和播放状态。精选/推荐流换视频时会用播放器当前视频标识隔离观察缓存，并终止旧视频
  的时间轴扫描；未加载、没有身份属性或尚未在页面出现的弹幕不会被猜测进来。
- 抖音评论：在评论“三个点”菜单里的「举报评论」旁可以点击「🚫 本地拉黑」，即使该菜单是
  portal 下的 `role="tooltip"` 普通文本项，也会复用你刚打开的那条评论上下文识别作者；只对实际的「举报评论」叶子项注入，避免同一提示层出现多个重复按钮；如果身份不可靠，不会注入按钮。右下角同列上方的「🚫 抖音评论屏蔽(N)」

  只读滚动评论容器触发懒加载，之后可全选或逐个勾选作者批量屏蔽。平台回收、未加载或没有明确展开控件的评论不会被猜测成“全部”。

### 各平台身份填写说明
| 平台 | 在设置里选 | 填什么 |
|---|---|---|
| B站 | B站 uid | 数字，如 `2233`（主页 URL `space.bilibili.com/2233`） |
| 微博 | 微博 uid | 数字，如 `1234567890` |
| 知乎 | 知乎 token | 个人页 URL `zhihu.com/people/这里` 的 slug |
| 贴吧 | 贴吧 uid | 旧版楼层 `data-field` 中的数字 `user_id`；新版详情评论使用已捕获的 Vue `userInfo.id` 数字值（首页 `.thread-card` 暂不支持） |
| X | X handle | 不带 @ 的用户名，如 `elonmusk` |
| 抖音 | 抖音 sec_uid | `MS4wLjAB...` 那串（作者主页 URL 里） |

> 最稳妥的方式还是**在网页上右键拉黑**——脚本会自动从页面里抓到正确的身份，不用你手填。
> 手动添加和导入都会走同一套身份规范化：数字 UID 会去掉无意义前导零，X handle 会去掉 `@` 并转为小写，未知身份前缀会跳过。名单中的备注按纯文本显示。

### 快捷拉黑（一键识别 + 锚定在原生按钮旁）

除了右键/悬停，脚本还会**自动在平台原生"拉黑/举报"按钮旁边**，插入一个「🚫 本地拉黑」入口——不用你手动找，点一下就识别并拉黑当前用户：

- **评论区 / 用户主页**：在平台自带的「拉黑」「加入黑名单」等菜单项**下方**，多出一个「🚫 本地拉黑」。点它，脚本沿 DOM 链（含 Shadow DOM）自动识别对应用户并弹出确认。
- **B站评论区**：当前页面的 `bili-comment-menu` 内会在「加入黑名单」后插入「🚫 本地拉黑」。
  根评论和当前真实 `bili-comment-reply-renderer` 楼中楼均使用各自 UID；屏蔽楼中楼只会让
  对应回复无占位消失，不会隐藏整条根评论线程。
- **B站主评论的「🧵 屏蔽该楼回复」**：会按评论接口返回的 `page.num`、实际 `page.size` 和 `page.count`
  读取该楼的后续子评论页，再与当前页面记录合并；接口失败、提前返回空页或达到安全分页上限时，会明确提示「部分」，
  不把当前页冒充成完整楼层。
- **B站内容作者**：视频页作者名旁、动态详情页作者模块旁显示「本地拉黑作者」；按钮通过
  独立门户贴近作者行，不插入 B站 Vue 管理的正文节点。视频作者使用空间链接 UID，动态作者
  使用页面作者状态中的可靠 mid，身份不可解析时不注入。
- **B站弹幕**：固定使用右下角「弹幕屏蔽(N)」工具展示脚本已从弹幕段解析出的发送者；
  即使播放器首段请求被 PAKKU 等扩展接管，入口也不会消失，并会用当前视频 `cid` 主动
  只读获取首段兜底。工具按文案聚合重复弹幕，单条按钮和勾选批量都会展开组内所有
  `mid_hash`，按发送者去重后逐人保存。普通弹幕段不直接提供昵称或 UID，所以默认名单
  仍显示 `bili:dmhash:<hash>`。可点 `UID?` 使用 PAKKU 同类算法反查 1–10 位数字候选，再
  匿名请求 B站用户卡片接口剔除不存在账号。唯一候选已通过卡片正向校验，按钮直接是
  「拉黑本人」，点击后同时保存昵称、UID 与 hash 并覆盖该 UID 的评论，不再二次确认；
  CRC32 碰撞下存在多个存活候选时仍要求打开主页核对，确认后才会合并身份。只按 hash
  屏蔽时，评论仍需另行屏蔽；同一 hash 的后续弹幕则会继续过滤。
  右侧原生弹幕列表会按显示时间按需读取对应数据段；唯一匹配的行显示「本地拉黑」，同文案
  多发送者的行显示「本地拉黑全部(N)」并在确认后逐 hash 屏蔽，尚未读取或暂未匹配的行显示
  禁用状态，不会伪造身份。
- **B站播放器里悬停弹幕**：把鼠标移到播放中的弹幕上，弹幕旁边会浮出「🚫 拉黑该弹幕
  发送者」，不必再去弹幕列表里翻同一条。B站的弹幕层本身不接收鼠标事件（CSS 写死
  `pointer-events: none`），所以脚本按指针坐标判断你指向的是哪一条，而不依赖网站是否
  弹出原生弹幕操作条。按钮会在弹幕移动时跟随目标。只有该弹幕的文案在已解析数据段中唯一对应一个 `mid_hash` 时才会
  出现；同一文案有多个发送者时身份不唯一，脚本不提供这个入口，改由右下角工具按文案
  分组批量处理。若你已登录且网站弹出了自带的弹幕「举报」菜单，脚本会在该项旁统一显示
  「🚫 本地拉黑」，并复用同一身份。
- **抖音弹幕**：弹幕层同样写死 `pointer-events: none`，但弹幕节点自身可接收鼠标事件。
  脚本把位于弹幕文字左侧并略有重叠的「🚫 拉黑」按钮挂进弹幕节点内，随滚动弹幕一起移动；点击后按
  `data-danmaku-user-id` 保存 `douyin:uid`，该弹幕和后续同发送者弹幕零占位消失。
  `data-is-danmu-author="true"` 的作者弹幕会额外映射当前视频作者 sec_uid，屏蔽作者本人
  时作者弹幕一并隐藏。没有身份属性的弹幕不显示按钮、不会被误隐藏。
- **微博评论**：当前详情页和用户主页帖子内的单条评论操作区常驻「本地拉黑」，使用该行自己的 UID；
  根评论与楼中楼都覆盖（真站结构分别是 `.item1 > .item1in > .con1 > .info > .opt` 和
  `.item2 > .con2 > .info > .opt`），也兼容 `node-type="reply_list"` / `.list_ul` /
  `.WB_reply` 这类旧版结构。点击「共 N 条回复」展开的弹窗中，根评论与回复行同样各自
  解析身份并挂载入口；评论中的回复对象或 `@提及` 不会被当作评论作者，展开行本身没有
  作者身份，不会出现入口。微博把顶层评论交给虚拟列表回收时，脚本也会识别被包裹的
  `.item1`，遇到异常的超大 `transform` 会按实际相邻行高度重建补位，避免屏蔽一条后下面
  的评论整体跑到页面外。用户主页帖子内的页内评论展开后，嵌套在帖内 `wbpro-list` 的评论
  不会被误当成整条帖子虚拟行，屏蔽时不会把该帖或下方帖子一起移位。
- **抖音评论**：评论“三个点”菜单里的「举报评论」旁会出现「🚫 本地拉黑」，只在最近打开的
  评论能可靠解析 sec_uid 时注入。右下角管理器会自动尝试展开带明确回复语义的入口，支持搜索已加载
  作者并按需滚动触发懒加载；没有可靠身份或没有明确展开控件时不注入、不猜测。
- **微博帖子作者**：正文作者行和旧版信息流卡片作者名旁显示「本地拉黑作者」，使用帖子
  作者自己的 UID；没有可靠作者链接时不注入。
- 入口靠**菜单文字 + 可验证身份上下文**匹配；没有身份时宁可不显示，也不放一个点击后报错的入口。
- 两个开关都在设置面板里：`本地拉黑入口` 控制平台原生菜单旁的快捷入口和 B站弹幕工具；
  `批量拉黑入口` 控制页面/弹幕管理器及其勾选批量按钮。

> 为什么可靠：快捷入口复用当前平台适配器的身份提取结果，并统一生成规范身份 key；
> 没有可靠身份时不注入入口，避免出现“拉了黑却没隐藏”的孤儿 key。

### 一键拉黑全部（批量）

- **B站视频页左下角浮层**「🚫 拉黑已加载评论作者(N)」：点击后先弹范围面板，可选
  「仅当前已加载」或「加载全部评论与子回复」（只读分页抓取公开评论接口，含未展开的
  楼中楼作者；任何一页失败都会提示“部分分页未取全”，不会伪装成完整名单）。还可按
  「晚于该时间点」筛选发言（最近 1/6/24 小时、3/7 天或自定义时间），缺少可靠时间的
  记录自动跳过。统计始终按 UID 去重，不会把右侧推荐视频卡误算为用户；原生举报、登录
  等弹窗打开时该浮层会隐藏，避免出现无意义的 `(0)`。
- **微博左下角浮层**「🚫 拉黑已加载微博/评论作者(N)」：详情页同时统计发帖人、已加载
  评论和已展开楼中楼回复，并按 UID 去重；未加载的评论不会虚构进计数。
- 抖音评论详情侧栏即使使用带 `Modal` 的外层 class，只要它实际承载评论，页面批量入口仍会显示。
- **抖音评论右下角浮层**「🚫 抖音评论屏蔽(N)」：打开后自动尝试展开当前页面可安全识别的
  回复入口，管理器显示已加载的根评论与子评论作者，支持搜索、全选、批量屏蔽和「尽量加载评论」；
  它不调用平台私有接口，虚拟/懒加载列表仍以页面实际加载结果为准。
- **抖音弹幕右下角浮层**「🚫 抖音弹幕屏蔽(N)」：打开后管理当前视频已经观察到的弹幕发送者，
  通过搜索、全选或勾选后批量屏蔽；已经屏蔽的发送者仍以灰色行保留，并可点「取消屏蔽」，不会被全选或
  批量操作再次选中；自动规则命中的行改为提供「恢复并例外」，恢复后当前平台自动规则会跳过该发送者，
  例外可在设置中点「恢复规则」删除。「尽量加载弹幕」只读扫描当前播放器时间轴并恢复播放状态；扫描进行中关闭管理器会立即取消并恢复关闭前的播放头，不能保证平台没有渲染或已回收
  的弹幕出现。按钮和弹窗只在视频页且“批量拉黑入口”开启时显示，切换视频会清空上一视频的观察列表，不会
  把上一视频的发送者带到新视频。
- **用户列表弹窗内**：弹窗里只要实际列出可解析身份的用户链接（微博点赞、转发、粉丝
  列表等），弹窗头部就会出现「🚫 拉黑全部(N)」，只有一位用户时也可用。视频页对普通
  观众并没有可枚举的“谁赞了”列表时，脚本不会虚构这个入口。弹窗关闭复用后，上一次
  的按钮会被清掉再重新统计。
- 批量拉黑会把每位用户保存为独立人物记录；点撤销时只删除这一次新增的身份，不会误删此前已经在名单中的用户。
- 适合"某条评论/视频下面一群人全在 output 恶心内容"时快速清场；同样可在设置里关闭。

## 设计与风控要点

- **抖音推荐流自动切是唯一的"模拟操作"**，为防雷控设了四道安全阀：① 仅在命中黑名单时触发；② 同一视频只切一次，页面复用节点展示新视频时重新判断；③ 200–600ms 随机延迟，并在执行前再次确认当前视频和作者仍命中；④ 连续跳过上限（默认 6 次，`0` 为不限制）超限即停在遮罩不再自动切。设置里可一键降级为纯遮罩。
- **绝不写 `media.muted`** 来静音被跳过视频——抖音把静音当全局偏好，写它会污染你正常刷视频的静音状态（这是 Pynseq 踩过的坑，已规避）。改用视觉遮罩。
- **所有拉黑入口都是自建 UI**，绝不触发平台原生"不感兴趣"或官方拉黑，避免污染推荐模型。
- **B站弹幕**在页面拿到数据前拦截实际的 `seg.so` / `list.so` 弹幕段，并在错过首段时按
  当前视频 `cid` 主动只读读取一次；手写轻量 protobuf 解析 `progress`、`mid_hash`、内容。
  检测到 PAKKU 时只桥接其公开 XHR 回调，不覆盖普通评论、图片和视频分片请求；普通请求仍
  直接沿页面原有链路通过。`bili:uid:N`
  经 CRC32 正向映射，或工具直接保存 `bili:dmhash:<hash>`。UID 候选查询只在用户主动点击
  后初始化约 1 MB 的本地反查表并校验公开用户卡片；未确认候选不会成为身份键，也不会
  改写 `view` 元数据响应。
