# OmniBlock v0.63.2 — 数据安全修复与桥接根因修复（合并发布）

两项修复合并为 v0.63.2 单一发布：degraded 存储只读降级（数据安全，critical）+ 桥接就绪快照分块与事件日志孤儿清理（根因修复，high）。

## 用户可见变化

- 存储桥接未就绪（degraded）时整页只读降级：名单与设置变更只在当前页内存生效、绝不写回存储，本地快照也不新增——空名单永远不会覆盖真实数据（此前 degraded 页面上改设置/确认拉黑会把空态写回并覆盖名单，2026-10-29 抢救报告记录的备份环覆盖即同一链路）。设置面板顶部与右下角持续警示「存储桥接未就绪，本页为只读降级模式：名单与设置变更不会保存」（浮条可关闭，面板警示保留）；存储恢复后刷新页面即可读回真实名单。Tampermonkey 正常安装路径行为不变。
- 桥接就绪快照按 2MiB 分块投递：本机事件日志较多不再导致桥接永久无法就绪——2026-09-12 起六平台页面全部 degraded 的状态解除，页面恢复读回真实名单。
- 事件日志按日期口径清理索引外的过期孤儿分片（含降级时代产生的大分片；保留期 30 天的既有语义不变，只删除本脚本自己的分片键）；`EventLog.status()` 新增 `orphanSweeps`/`orphanShardsDeleted` 诊断计数。

## 证据

### real-site verified
- 2026-10-30 专用 Chrome 登录态只读探针（`node test/maintenance-check.cjs --dedicated-only`，用户本人专用浏览器 profile，CDP 9222）：扩展刷新到 0.63.2 后四个可达平台桥接全部 ready（bilibili/douyin/weibo 1 尝试 0 拒绝、zhihu 2 尝试 0 拒绝），真实读取正常——脱敏 `bilibili.com/page/...` content=8（withIdentity 8/8）、`weibo.com/page/...` content=6 users=6（withIdentity 6/6）、`douyin.com/jingxuan/...` content=10（withIdentity 0/10 为页面级登录/安全门禁既有状态）；同一运行的刷新环节先捕获旧扩展 0.63.0 的 degraded（8 尝试 8 拒绝 ready-timeout）再捕获 0.63.2 ready（attempts=2），构成修复前后直接对照——2026-09-12 起六平台永久 degraded 在真实存储上解除。

### structure regression
- 新增 `test/degraded-storage.cjs` 两阶段 10 项：>8MiB 真实同机制夹具断言分块 ready（BR-1..5：ready 成功、2 个种子人物读回、degraded===false、40 天孤儿分片被清理、ready 放行对照 setSetting 落盘且种子名单未被覆盖）；http 页面 fallback 断言 degraded 只读（STORE-1..4：`data:v1`/`backup:v1` 字节不变、警示 UI 出现且浮条关闭后面板警示保留）。六项核心断言在旧行为上实测失败（含 data:v1 被空态覆盖的 SHA-256 字节级对照 `6be1e28e…`→`4186f9d7…`、backup:v1 468→2,365 字节），旧行为基线以 git worktree 运行 HEAD（0.63.0）留证；修复后 10/10。
- `test/dev-extension.cjs` 13/13（"就绪快照分块协议两侧同步"与"桥接双层写入门控存在"源码级守卫，旧模板上失败；ready 共享存储、伪造消息拒绝、AI 直连拒绝、缺隔离桥 8 次有界降级等既有用例保留）；`test/run.cjs` 20/20、`test/dark-mode.cjs` 全部通过、`test/product-extension.cjs` 3/3（产品构建共用桥接模板）。
